│  자료가 없으면 │  │ [__________] │  │   │ │ [__________] │ │

## 5. FEAT-UI-001 : 사이드바 폭 조절

**개요:** 데스크톱에서 사이드바와 본문 사이 경계를 끌어 폭을 바꾼다. 값은 브라우저에 기억한다.

**화면:** SCR-CHAT-001 (`/`) — `md` 이상에서만

**입력값:**

| 필드 | 타입 | 필수 | 검증 규칙 |
|------|------|------|---------|
| 포인터 X 좌표 | number | Y | 드래그 중 매 프레임 |
| 저장된 폭 | number | N | `localStorage` — 범위를 벗어난 값은 무시하고 기본값을 쓴다 |

**처리 흐름:**

1. 경계의 손잡이를 누르면 드래그가 시작된다
2. 움직이는 동안 사이드바 폭이 **포인터를 그대로 따라간다** (트랜지션 없음)
3. 손을 떼면 그 폭을 `localStorage` 에 저장한다
4. 다음 방문에 저장된 폭으로 연다

**규격:**

| 항목 | 값 |
|------|-----|
| 기본 폭 | 260px |
| 최소 · 최대 | 200px · 420px |
| 손잡이 | 폭 4px(투명), 가리키면 `accent` 로 1px 선이 드러남 |
| 저장 키 | `rag_chatbot_sidebar_width` |
| 되돌리기 | 손잡이를 더블클릭하면 기본 폭 |
| 키보드 | 손잡이에 포커스 후 ← / → 로 16px 씩 |

**예외 처리:**

| 상황 | 처리 방식 |
|------|---------|
| 최소·최대를 넘겨 끎 | 경계에서 멈춘다. 화면 밖으로 사라지는 사이드바를 만들지 않는다 |
| 저장된 값이 범위 밖(수동 변조 · 규격 변경) | 무시하고 기본 폭으로 연다 |
| 드래그 중 텍스트가 선택됨 | 드래그 동안 `user-select: none` 을 건다 — 안 걸면 화면이 파랗게 반전돼 고장난 것처럼 보인다 |
| 모바일(드로어) | 손잡이를 그리지 않는다. 폭은 `min(84vw, 320px)` 고정 |

**접근성:** 손잡이는 `role="separator"` · `aria-orientation="vertical"` · `aria-valuenow/min/max` 를 갖고
탭으로 닿는다. 마우스가 없으면 조절할 수 없는 기능을 만들지 않는다.

**범위 밖:** 사이드바 접기(0px 토글)는 이번에 하지 않는다 — 접힘 상태의 헤더·본문 배치가 따로 필요하다.

## 6. 테스트 계획

시각(색 · 여백)은 테스트로 잡지 않는다. 클래스 문자열을 단언하면 디자인을 고칠 때마다 테스트가 깨져
게이트가 아니라 마찰이 된다. **동작이 있는 것만** 잡는다.

| 대상 | 케이스 | 결과 |
|------|--------|------|
| 폭 조절 (`frontend/src/components/chat/ResizableSidebar.test.tsx`) | 끌면 폭이 바뀜 · 최소/최대에서 멈춤 · 저장값으로 복원 · 범위 밖 저장값 무시 · 더블클릭 초기화 · ←/→ 키 조절 | 6건 통과 |
| 기존 케이스 | 색·클래스 변경이 텍스트·role 기반 단언을 깨뜨리지 않는지 | 통과. 다만 **바뀐 문구 2건**(빈 화면 인사 · 로그인 부제)은 단언을 새 문구로 맞췄다 |

측정 : 2026-08-18 · 프론트 전체 **59건 통과**. `scripts/case-floors.env` 의 `FRONTEND_MIN` 52 → 59.
