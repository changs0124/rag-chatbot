> **현재 상태** — `users` 테이블에 권한 컬럼이 **없다.** 지금은 로그인한 전원이 동등하다.
> 이 문서는 REQ-ADMIN-004가 신설할 체계를 정의한다. `ADMIN` 열은 전부 **미구현**이다.

## 1. 역할 정의

| 역할 | 코드 | 설명 | 부여 방식 |
|------|------|------|---------|
| 비회원 | `GUEST` | 로그인하지 않은 상태. 저장되는 역할이 아니라 "인증 없음"을 가리키는 이름이다 | — |
| 일반 회원 | `USER` | 가입한 사용자. `users.role` 기본값 | 자유 가입 |
| 관리자 | `ADMIN` | RAG 문서와 계정을 관리한다 | **환경변수 `ADMIN_EMAILS` 명단** |

### 1.1 관리자 부여 방식 결정(2026-08-19)

| 안 | 채택 | 사유 |
|----|------|------|
| 환경변수 `ADMIN_EMAILS` 명단 | **채택** | 앱 안에 권한 상승 API가 존재하지 않는다. 공격면이 늘지 않고 통제권이 배포 설정에 남는다 |
| 첫 가입자 자동 승격 | 기각 | DB 초기화 시점에 외부인이 먼저 가입하면 그가 관리자가 된다 |
| DB 수동 UPDATE | 기각 | 배포마다 DB 접속이 필요하고 절차가 문서에만 존재하게 된다 |

**동기화 규칙** : 기동 시 명단에 있는 계정을 `admin` 으로 올리고, **명단에서 빠진 계정은 `user` 로 내린다.**
승격만 하고 강등을 안 하면 한 번 관리자가 된 계정이 명단에서 지워도 영구히 남는다.

**감수하는 약점** : 명단 변경에 재기동이 필요하다. 사내 소규모에서 관리자 교체는 드물어 감수한다.

### 1.2 역할을 JWT에 담지 않는 이유

역할을 토큰 클레임에 넣으면 **강등이 토큰 만료까지 반영되지 않는다.** 현재 인증 필터는 이미
요청마다 사용자 행을 읽고 있으므로(비밀번호 변경 시각 대조), 같은 조회에서 역할을 함께 읽는다.
추가 쿼리가 없다.

## 3. 데이터 접근 범위

| 역할 | 접근 가능 데이터 범위 |
|------|-------------------|
| `GUEST` | 헬스체크 · 로그인/가입 엔드포인트 · 서명 토큰이 있는 첨부 |
| `USER` | 본인 대화·메시지·출처·첨부 |
| `ADMIN` | `USER` 범위 + RAG 문서 전체 + 사용자 목록(계정 정보) |

**관리자도 남의 대화 데이터에는 접근할 수 없다.** 위 표에서 `ADMIN` 의 확장 범위는 대화가 아니라
**문서와 계정**이다.

## 4. 권한 거부 응답 규칙

**권한 없음을 403이 아니라 404로 돌려준다.** 소유권 위반과 같은 규칙(P-3)이다.

| 상황 | 응답 | 사유 |
|------|------|------|
| 미인증 | `401` | 인증하면 될 수도 있다는 정보는 숨길 이유가 없다 |
| 인증됐으나 권한 없음 | **`404`** | 403은 "거기 뭔가 있다"를 알려준다. 관리 기능의 존재 자체를 드러내지 않는다 |
| 남의 리소스 접근 | `404` | 위와 같다 |

일반적인 REST 관행(403)과 다르며, **의도된 선택**이다. 프론트도 이 규칙을 전제로 만든다.

## 5. 특수 권한

| 권한명 | 대상 역할 | 설명 |
|--------|---------|------|
| 서명 경로 토큰 | 첨부 소유자 | `<img src>` 가 Authorization 헤더를 실을 수 없어 쿼리 토큰으로 검증한다. TTL 15분이며 조회 시점마다 새로 발급된다 |
| 목업 모드 | — | `APP_MODE=mock` 은 권한이 아니라 실행 모드다. 인증·권한 규칙은 목업에서도 동일하게 적용된다 |

## 6. 프론트와 서버의 역할 분담

| 계층 | 하는 일 | 하지 않는 일 |
|------|--------|-------------|
| 프론트 | 역할에 따라 메뉴·라우트를 **보여줄지 말지** 정한다 | 접근을 막는 최종 판단 |
| 서버 | 모든 요청에서 권한을 검사한다 | — |

**프론트의 가드는 편의다. 유일한 방어선은 서버다.** 라우트 가드가 있다는 이유로 서버 검사를
생략하지 않는다.
