## 2. 플로우 상세

### FLOW-AUTH-001: 로그인 · 세션 유지

```mermaid
flowchart TD
    A([시작]) --> B[로그인 화면]
    B --> C[이메일 · 비밀번호 입력]
    C --> D{분당 시도 상한}
    D -- 초과 --> E[429 - 잠시 후 다시]
    E --> C
    D -- 통과 --> F{계정 · 비밀번호 일치}
    F -- 불일치 --> G["401 - 이메일 또는 비밀번호가 올바르지 않음<br/>(계정 유무를 구분하지 않음)"]
    G --> C
    F -- 일치 --> H[토큰 발급 · localStorage 저장]
    H --> I[채팅 화면]
    I --> J[API 요청]
    J --> K{남은 수명 &lt; 임계}
    K -- 예 --> L["X-Refresh-Token 헤더로 새 토큰<br/>프론트가 setToken 교체"]
    L --> I
    K -- 아니오 --> M{토큰 유효}
    M -- 유효 --> I
    M -- 만료·무효 --> N[401 → 로그인 화면]
    N --> B
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| 계정 미존재 · 비밀번호 불일치 | **같은 401 응답**. 존재를 은닉한다 |
| 분당 로그인 시도 초과 | 429. 키는 정규화된 이메일이며 IP가 아니다 |
| 남은 수명 < `JWT_REFRESH_THRESHOLD_MINUTES` | 응답 헤더로 새 토큰 (미구현) |
| 비밀번호 변경 이후의 옛 토큰 | 401. `password_changed_at` 기준선에 걸린다 |
| **자격 증명 경로(`/auth/login` · `/auth/signup` · `/profile/password`)의 401** | **로그아웃시키지 않는다.** "방금 넣은 값이 틀렸다"는 뜻이다 |

**임계가 0이면 재발급을 하지 않는다** — 종전 고정 만료 동작으로 되돌리는 경로다.

### FLOW-CHAT-001: 채팅 한 턴

```mermaid
flowchart TD
    A([전송]) --> B{분당 상한}
    B -- 초과 --> C[429]
    B -- 통과 --> D{동시 스트림 상한}
    D -- 초과 --> E[429 - 큐에 쌓지 않음]
    D -- 획득 --> F{소유권 · 입력 검증}
    F -- 실패 --> G["400 / 404<br/>(SSE 아닌 정상 HTTP)"]
    G --> H[상한 해제]
    F -- 통과 --> I[사용자 메시지 저장 · 첨부 연결]
    I --> J[SSE 개시 - meta]
    J --> K[stage: 질문 분석 중]
    K --> L{file_search 호출됨}
    L -- 예 --> M[stage: 참조 문서 검색 중]
    L -- 아니오 --> N[단계 생략]
    M --> O[stage: 답변 작성 중]
    N --> O
    O --> P[token 스트림]
    P --> Q{어떻게 끝났나}
    Q -- 정상 --> R["답변 + 출처 원자적 저장<br/>citations → done"]
    Q -- 사용자 중단 --> S["부분 텍스트를<br/>complete + stopped=true 로 저장"]
    Q -- 오류 --> T["부분 텍스트를 error 로 저장<br/>event: error"]
    R --> U([종료])
    S --> U
    T --> U
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| 동시 스트림 상한 초과 | 429. **`prepare` 앞에서 획득한다** — 뒤에서 거절하면 답변 없는 사용자 메시지가 대화에 남는다 |
| `file_search` 이벤트가 안 옴 | **검색 단계를 보내지 않는다.** 근거 없는 단계를 만들지 않는다(P-10) |
| 첫 토큰 이후 도착한 단계 | 보내지 않는다. 답변이 시작된 뒤 진행 단계를 올리면 순서가 거꾸로 보인다 |
| 사용자 중단 | **실패가 아니다.** 받은 데까지 `complete` 로 저장한다 |
| 중단인데 받은 것이 없음 | **아무것도 저장하지 않는다.** 빈 버블을 남기면 새로고침에 사라져 화면과 재조회가 어긋난다 |
| 완료 이벤트 없이 스트림 종료 | **오류로 처리한다.** 조용히 무자료 성공으로 위장하지 않는다 |

### FLOW-CHAT-002: 첨부 즉시 업로드

```mermaid
flowchart TD
    A([파일 선택 · 드롭 · 붙여넣기]) --> B{이미지인가}
    B -- 아니오 --> C[조용히 버림 - 카드도 안 만듦]
    B -- 예 --> D[objectURL 로 카드 즉시 표시]
    D --> E[POST /api/files 시작 - uploading]
    E --> F{결과}
    F -- 성공 --> G[카드에 id 부착 - done]
    F -- 실패 --> H[카드 error + 재시도]
    D --> I{업로드 중 카드 제거}
    I -- 예 --> J[AbortController 로 요청 끊음]
    J --> K{뒤늦게 성공했나}
    K -- 예 --> L["DELETE /api/files/id<br/>서버가 이미 받은 것을 지움"]
    K -- 아니오 --> M([끝])
    G --> N{보내기}
    H --> O["보내기 비활성<br/>재시도하거나 지워야 함"]
    N --> P[올라간 id 목록으로 전송]
    P --> Q[카드 비우고 objectURL 회수]
    Q --> R([종료])
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| 업로드 중 · 실패 카드가 있음 | **보내기 버튼 비활성.** 빠진 채 전송되는 경로를 막는다 |
| 지운 카드의 업로드가 뒤늦게 성공 | 서버에서 지운다. 중단은 요청을 끊을 뿐 **서버가 받은 것을 되돌리지 않는다** |
| 전송하지 않고 화면을 떠남 | `message_id=null` 고아. 회수 크론이 유예 뒤 정리 |
| objectURL 회수 누락 | 탭 메모리가 계속 늘어난다. 회수 지점은 **카드 제거 · 전송 완료 · 언마운트** 세 곳 |

### FLOW-RAG-001: 무자료 판정

```mermaid
flowchart TD
    A([스트림 종료]) --> B{Vector Store 설정됨}
    B -- 아니오 --> C["file_search 를 붙이지 않았음<br/>→ 인용 0건"]
    B -- 예 --> D[응답 annotations 파싱]
    D --> E{file_citation 이 있나}
    E -- 있음 --> F[출처 목록 생성 - seq 1부터]
    E -- 없음 --> G[인용 0건]
    C --> G
    F --> H[noSource = false]
    G --> I[noSource = true]
    H --> J[각주 표시]
    I --> K{stopped 인가}
    K -- 예 --> L["배너를 붙이지 않음<br/>출처 판정 전에 끝났으므로"]
    K -- 아니오 --> M["'자료 없음 - 추론으로 답변함' 배너"]
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| `OPENAI_VECTOR_STORE_ID` 미설정 | 검색을 아예 하지 않아 **모든 답변이 무자료**가 된다 |
| 인용 0건 + `stopped=false` | 무자료 배너 |
| 인용 0건 + **`stopped=true`** | **배너를 붙이지 않는다.** 중단은 인용이 오기 전에 끝나 항상 0건이라, 붙이면 100% 거짓이 된다 |
| 검색은 됐으나 본문이 인용하지 않은 파일 | 출처에서 제외한다. 검색된 것과 인용된 것은 다르다 |

**판정 규칙은 Mock · Real 공통으로 `citations.isEmpty()` 하나다.** 텍스트 접두가 아니라 플래그로
알리는 이유는, 라이브에서 인용 유무를 스트림이 끝나야 알 수 있어 **이미 흘려보낸 토큰 앞에 접두를
붙일 수 없기** 때문이다.

### FLOW-ADMIN-001: RAG 문서 업로드 (미구현)

```mermaid
flowchart TD
    A([파일 선택]) --> B{관리자인가}
    B -- 아니오 --> C[404 - 존재 은닉]
    B -- 예 --> D{Vector Store 설정됨}
    D -- 아니오 --> E["400 - 스토어 미설정<br/>행을 만들지 않음"]
    D -- 예 --> F{형식 · 크기 · 매직바이트}
    F -- 위반 --> G[400 - 허용 목록 안내]
    F -- 통과 --> H[OpenAI Files 업로드]
    H -- 실패 --> I["502<br/>아무것도 안 남음"]
    H -- 성공 --> J[Vector Store 연결]
    J -- 실패 --> K["파일 삭제 시도<br/>실패 시 경고 로그<br/>행은 만들지 않음"]
    J -- 성공 --> L[rag_documents 기록 - in_progress]
    L -- 실패 --> M["연결 해제 시도<br/>실패 시 file_id 를 경고 로그에<br/>(가장 나쁜 상태)"]
    L -- 성공 --> N[목록에 표시]
    N --> O{5초 폴링}
    O --> P{status}
    P -- in_progress --> O
    P -- completed --> Q([검색에 잡힘])
    P -- failed --> R["⚠ 실패 + 설명<br/>'답변 근거로 쓰이지 않습니다'"]
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| 비관리자 | 404. 403이 아니다 |
| 스토어 미설정 | 400. **행을 만들지 않는다** — 어디에도 없는 문서가 목록에만 뜨는 상태를 막는다 |
| 4단계 실패 | OpenAI에 고아 파일. 즉시 삭제 시도 |
| 5단계 실패 | **스토어에는 있는데 기록이 없다.** 화면에서 안 보이니 지울 수도 없어 가장 나쁘다 |
| `in_progress` 행이 하나도 없음 | **폴링을 멈춘다.** 안 멈추면 배경에서 계속 돈다 |
| 인덱싱 실패 | 아이콘만 두지 않고 **한 줄 설명을 붙인다.** 아이콘만 보면 "올라갔으니 됐다"고 읽는다 |

### FLOW-ADMIN-002: 관리자 권한 동기화 (미구현)

```mermaid
flowchart TD
    A([기동]) --> B{ADMIN_EMAILS 설정됨}
    B -- 아니오 --> C[관리자 0명 - 기동은 정상]
    B -- 예 --> D[콤마 분리 · 소문자 정규화]
    D --> E[명단에 있는 계정 → role=admin]
    E --> F["명단에서 빠진 계정 → role=user<br/>(강등을 안 하면 영구히 남음)"]
    F --> G{명단에 있으나 미가입}
    G -- 예 --> H[아무 일도 안 함]
    H --> I[가입 시점에 명단을 다시 봄]
    G -- 아니오 --> J([완료])
    I --> J
```

**분기 조건:**

| 조건 | 결과 |
|------|------|
| 대소문자가 다른 이메일 | 정규화 후 비교하므로 승격된다 |
| 명단에서 이메일을 지움 | **다음 기동에 강등된다.** 승격만 하면 한 번 관리자가 된 계정이 영구히 남는다 |
| 명단에 미가입 이메일 | 기동을 막지 않는다. 가입 시점에 반영된다 |
| 명단 변경 | **재기동이 필요하다.** 감수하는 약점 |

**역할을 JWT에 담지 않으므로 강등이 즉시 반영된다.** 담았다면 토큰 만료까지 관리자로 남는다.
