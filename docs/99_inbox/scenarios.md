## 1. 테스트 범위 요약

| 카테고리 | 케이스 수 | 우선순위 | 자동화 |
|---------|---------|---------|--------|
| 첨부 카드 · 업로드 (CHAT-001) | 8 | High | 8 |
| 확대 보기 (CHAT-002) | 8 | High | 8 |
| 드롭 · 붙여넣기 (CHAT-003) | 2 | Medium | 2 |
| 엣지 케이스 | 5 | Medium | 3 |

케이스가 늘어나므로 `scripts/case-floors.env` 의 `FRONTEND_MIN` 을 실측값으로 함께 올렸다 — 32 → **59**
(프론트 전체 기준. 이 문서의 21건과 재디자인 6건 외에 기존 케이스가 포함된 수다).

**공통 사전 조건** : jsdom 에 `URL.createObjectURL` · `revokeObjectURL` · `PointerEvent` 가 없다.
앞의 둘은 테스트에서 스텁으로, `PointerEvent` 는 `frontend/src/test/setup.ts` 폴리필로 심는다 —
없으면 핀치 검사가 "아무 일도 안 일어남"을 통과로 읽는다. 업로드·삭제 엔드포인트는 모듈 모킹으로 가른다.

### 첨부 카드 · 업로드 (FEAT-CHAT-001)

#### TC-CHAT-001: 이미지를 고르면 카드가 즉시 뜨고 업로드가 시작된다

| 항목 | 내용 |
|------|------|
| 관련 기능 | FEAT-CHAT-001 |
| 사전 조건 | 로그인 상태 · 채팅 화면(`/`) |
| 테스트 데이터 | `image/png` File (`photo_0001.png`) · 업로드 응답을 지연시킨 목 |

**시나리오:**

1. `+` 메뉴에서 사진을 고른다

**예상 결과:**

- 응답 전에 이미 카드의 `img` 가 objectURL 로 렌더된다
- 업로드 함수가 그 File 로 1회 호출된다
- 카드에 파일명 텍스트는 **없다** (`alt` · `aria-label` 로만 존재)

**상태:** `통과`
