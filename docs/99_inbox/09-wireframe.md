## 1. 설계 기준

- **브레이크포인트** : Tailwind 기본값. 이 화면이 실제로 가르는 지점은 `md`(768px) 하나다 —
  `md` 이상은 사이드바 상주, 미만은 오버레이 드로어(`frontend/src/pages/ChatPage.tsx`)
- **그리드** : 없음. 본문은 `max-w-3xl` 중앙 정렬 한 줄기다
- **디자인 도구** : 없음 (마크다운 설명 + Tailwind 유틸리티 클래스)
- **다크 모드** : 모든 신규 요소는 `dark:` 접두를 함께 둔다. `prefers-color-scheme` 을 직접 보지 않는다
- **참고한 것** : ChatGPT · Claude 채팅 입력창. 이미지는 파일명 없는 정사각 카드

### SCR-CHAT-001: 채팅

**URL:** `/`

#### 2-1. 입력창 첨부 카드 (FEAT-CHAT-001)

**변경 전 (지금)**

```
┌──────────────────────────────────────────────┐
│ [🖼] photo_0001.jpg ⊗ │ [🖼] IMG_22.png ⊗   │   ← 아이콘 + 파일명 칩
├──────────────────────────────────────────────┤
│ [+]  메시지를 입력하세요              [ ↑ ]  │
└──────────────────────────────────────────────┘
```

**변경 후 — 상태 3가지**

```
┌──────────────────────────────────────────────┐
│  ┌────┐⊗  ┌────┐⊗  ┌────┐⊗                  │  ← ⊗ 는 카드 모서리에 걸침
│  │■■■■│   │▨▨▨▨│   │ ⚠  │                   │
│  │■■■■│   │ ◐  │   │재시도│                  │
│  └────┘   └────┘   └────┘                    │
│   완료     업로드중   실패                     │
├──────────────────────────────────────────────┤
│ [+]  메시지를 입력하세요              [ ↑ ]  │
└──────────────────────────────────────────────┘
     ■ = 썸네일  ▨ = 흐리게 처리한 썸네일  ◐ = 진행 표시
```

- 업로드 중인 카드가 하나라도 있으면 **보내기 버튼이 비활성**이다
- 이미지가 아닌 파일은 카드조차 만들지 않는다(버림). `+` 메뉴도 **사진 · 카메라** 둘뿐이다

**Mobile (~767px)** — 카드 크기는 같고 줄바꿈만 늘어난다. 카드가 파일명을 안 쓰므로 좁은 화면에서도 한 줄에 3~4장 들어간다.

**UI 컴포넌트:**

| 컴포넌트 | 타입 | 설명 |
|---------|------|------|
| 첨부 카드 | `button` | 64px 정사각 · `object-cover` · 둥근 모서리. 누르면 확대 |
| 썸네일 | `img` | `src` 는 로컬 objectURL. `alt` 에 파일명 |
| 제거 버튼 | `button` | 카드 **우상단 모서리에 겹침**. `aria-label="첨부 제거"` |
| 진행 표시 | `div` | 업로드 중 카드 위에 반투명 겹침 + 스피너 |
| 실패 표시 | `div` | 경고 아이콘 + `재시도` 버튼. 서버 메시지는 title 로 |

**인터랙션:**

| 동작 | 결과 |
|------|------|
| 이미지 선택 · 촬영 · 드롭 · 붙여넣기 | 카드 즉시 생성 + 업로드 시작 |
| 카드 클릭 | 확대 모달 열림 (업로드 중이어도 열린다) |
| ⊗ 클릭 | 카드 제거 · 진행 중이면 요청 중단 · 올라갔으면 서버 삭제 · objectURL 회수 |
| 재시도 클릭 | 같은 파일로 업로드를 다시 시작 |
| 전송 | 카드 목록 비움 + objectURL 전부 회수 |

## 3. 관리자 화면 (FEAT-ADMIN-* · 미구현)

**추가 설계 기준** — 2절과 같은 규칙에 아래를 더한다.

- **재사용** : 삭제 확인은 `frontend/src/components/ConfirmModal.tsx`, 입력은
  `frontend/src/components/TextInput.tsx` 를 그대로 쓴다. 새로 만들지 않는다
- **레이아웃 기준** : 마이페이지(`frontend/src/pages/MyPage.tsx`)의 단일 컬럼 카드 구조를 따른다.
  관리 화면만 다른 골격을 쓰지 않는다

### 3-0. 진입점 (SCR-MY-001 변경)

관리자에게만 마이페이지에 메뉴가 하나 늘어난다. **비관리자에게는 아예 렌더링하지 않는다** —
눌러서 404를 만나는 것보다 없는 편이 낫다.

```
마이페이지 (/me)
┌────────────────────────────────────┐
│  프로필                             │
│  이름          [            ]      │
│  비밀번호 변경  [            ]      │
│  테마          ○ 라이트 ● 다크 ○ 시스템│
├────────────────────────────────────┤
│  관리                    ← admin 만 │
│  📄 문서 관리              →       │
└────────────────────────────────────┘
```

이 노출은 `GET /api/auth/me` 의 `role` 로 판단한다. **표시 판단일 뿐 접근 제어가 아니다.**
URL을 직접 쳐서 들어오는 경로는 서버가 404로 막는다.

### SCR-ADMIN-001: 문서 관리

**URL:** `/admin`

#### 3-1. 기본 상태 (md 이상)

```
┌──────────────────────────────────────────────────────────────┐
│  ← 마이페이지                                                 │
│                                                              │
│  문서 관리                                                    │
│  답변 근거로 쓰이는 사내 문서입니다. 여기 없는 내용은 답변에    │
│  출처로 붙지 않습니다.                                        │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │        파일을 끌어다 놓거나  [ 파일 선택 ]              │  │
│  │        PDF · TXT · MD · DOCX · 최대 50MB               │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  문서 4건                                                     │
│  ┌──────────────┬─────────┬──────────┬──────────┬────────┐  │
│  │ 이름          │ 상태     │ 크기      │ 올린 사람 │        │  │
│  ├──────────────┼─────────┼──────────┼──────────┼────────┤  │
│  │ 취업규칙.pdf  │ ● 완료   │ 2.4 MB   │ 김운영    │  삭제  │  │
│  │ 복리후생.pdf  │ ◐ 처리중 │ 1.1 MB   │ 김운영    │  삭제  │  │
│  │ 보안지침.docx │ ⚠ 실패   │ 0.8 MB   │ 이관리    │  삭제  │  │
│  │ FAQ.md       │ ● 완료   │ 12 KB    │ 김운영    │  삭제  │  │
│  └──────────────┴─────────┴──────────┴──────────┴────────┘  │
└──────────────────────────────────────────────────────────────┘
```

**UI 컴포넌트:**

| 컴포넌트 | 타입 | 설명 |
|---------|------|------|
| 업로드 영역 | `div` + `input[type=file]` | 드롭 · 클릭 양쪽 지원. 허용 형식을 문구로 명시 |
| 문서 표 | `table` | 5열. `md` 미만에서는 카드 목록으로 대체 |
| 상태 배지 | `span` | 아래 표 참고. 색은 토큰으로만 |
| 삭제 버튼 | `button` | `ConfirmModal` 로 확인 후 실행 |

**상태 표시:**

| 상태 | 표시 | 의미 |
|------|------|------|
| `completed` | ● 완료 (`text-accent`) | 검색에 잡힌다 |
| `in_progress` | ◐ 처리중 (`text-muted`) | 인덱싱 중. 아직 검색에 안 잡힌다 |
| `failed` | ⚠ 실패 (`text-danger`) | **검색에 안 잡힌다** |

**실패 행에는 한 줄 설명을 붙인다** — "인덱싱에 실패해 답변 근거로 쓰이지 않습니다".
상태 아이콘만 두면 관리자가 "올라갔으니 됐다"고 읽는다. REQ-ADMIN-003이 막으려는 것이 이 오독이다.

#### 3-2. 업로드 진행

파일을 고르면 표 맨 위에 행이 **즉시** 생기고 `◐ 업로드중` 으로 시작한다. 첨부 카드(2-1)와 같은
방식이다 — 네트워크를 기다렸다가 그리지 않는다.

```
│  │ 취업규칙_v2.pdf │ ◐ 업로드중 62% │ 2.4 MB │ 나 │      │  │
```

업로드가 끝나면 `◐ 처리중` 으로 바뀐다. **업로드 완료 ≠ 인덱싱 완료**이며, 이 둘을 같은 문구로
쓰지 않는다.

#### 3-3. 상태 갱신

`in_progress` 행이 하나라도 있으면 **5초 간격으로 목록을 다시 읽는다.** 전부 종료 상태가 되면 멈춘다.

- 폴링으로 하는 이유 : 인덱싱 완료를 알려줄 푸시 경로가 없다. SSE를 하나 더 만들 만한 빈도가 아니다
- 화면을 떠나면 멈춘다(`useEffect` 정리). 안 멈추면 배경에서 계속 돈다

#### 3-4. 삭제

기존 `ConfirmModal` 을 쓴다.

```
┌────────────────────────────────────┐
│  '취업규칙.pdf' 를 삭제할까요?       │
│                                    │
│  이 문서는 더 이상 답변 근거로       │
│  쓰이지 않습니다. 이미 나간 답변의   │
│  출처 표기는 그대로 남습니다.        │
│                                    │
│           [ 취소 ]  [ 삭제 ]        │
└────────────────────────────────────┘
```

**두 번째 문단이 중요하다** — 기존 대화의 각주는 `citations` 테이블에 영속화돼 있어 문서를 지워도
남는다. 이 사실을 안 알리면 관리자가 "지웠는데 왜 아직 보이지"라고 읽는다.

#### 3-5. 빈 상태

```
┌────────────────────────────────────────────┐
│              아직 문서가 없습니다            │
│                                            │
│   지금은 모든 답변이 '자료 없음' 으로        │
│   표시됩니다. 문서를 올리면 답변에           │
│   출처가 붙기 시작합니다.                   │
└────────────────────────────────────────────┘
```

문서 0건은 "검색은 되는데 결과가 없는" 상태가 아니라 **아직 시작하지 않은** 상태다.
그 차이를 문구로 밝힌다.

#### 3-6. 스토어 미설정

`OPENAI_VECTOR_STORE_ID` 가 비어 있으면 업로드 영역 대신 배너를 띄우고 **선택 버튼을 비활성한다.**

```
┌────────────────────────────────────────────┐
│  ⚠ Vector Store 가 설정되지 않았습니다      │
│  OPENAI_VECTOR_STORE_ID 를 넣고 다시        │
│  기동해야 문서를 올릴 수 있습니다.           │
└────────────────────────────────────────────┘
```

올릴 수 없는 상태에서 올릴 수 있는 것처럼 보이게 두지 않는다.

#### 3-7. md 미만 (모바일)

표 대신 카드 목록으로 떨어뜨린다. 열이 5개라 가로 스크롤이 생기면 삭제 버튼이 화면 밖으로 나간다.

```
┌──────────────────────────┐
│ 취업규칙.pdf              │
│ ● 완료 · 2.4 MB          │
│ 김운영 · 08/19            │
```

### SCR-ADMIN-002: 사용자 관리

같은 `/admin` 화면의 두 번째 섹션이다. 화면을 더 만들지 않는다.

```
│  사용자 3명                                                  │
│  ┌──────────────┬──────────────────┬────────┬────────────┐  │
│  │ 이름          │ 이메일            │ 권한    │            │  │
│  ├──────────────┼──────────────────┼────────┼────────────┤  │
│  │ 김운영        │ ops@company.com  │ 관리자  │            │  │
│  │ 박사원        │ park@company.com │ 사용자  │ 비밀번호   │  │
│  │                                            │  초기화   │  │
│  └──────────────┴──────────────────┴────────┴────────────┘  │
```

**자기 자신에게는 초기화 버튼을 띄우지 않는다** — 마이페이지에 비밀번호 변경이 이미 있고,
관리자가 자기 세션을 스스로 끊는 경로를 만들 이유가 없다.

#### 3-8. 초기화 결과

```
┌────────────────────────────────────────────┐
│  임시 비밀번호가 발급되었습니다               │
│                                            │
│      ┌──────────────────────┐              │
│      │  Xk7-mQ2p-9Vr4        │  [ 복사 ]   │
│      └──────────────────────┘              │
│                                            │
│  이 값은 지금만 볼 수 있습니다. 닫으면        │
│  다시 확인할 수 없습니다.                    │
│  박사원 님의 기존 로그인은 모두 해제되었습니다.│
│                                            │
│                          [ 닫기 ]           │
└────────────────────────────────────────────┘
```

두 문장 모두 필요하다. 앞은 **다시 못 본다**는 사실(서버가 평문을 저장하지 않는다),
뒤는 **그 사용자가 즉시 로그아웃된다**는 사실이다. 뒤를 안 알리면 관리자는 사용자가
"갑자기 튕겼다"고 문의할 때 원인을 연결하지 못한다.

### 3-9. 접근 제어 정리

| 경로 | 비로그인 | 일반 사용자 | 관리자 |
|------|----------|------------|--------|
| `/me` 의 관리 메뉴 | 안 보임 | **안 보임** | 보임 |
| `/admin` 직접 접근 | `/login` 리다이렉트 | 접근 불가 후 `/` 로 | 정상 |
| `/api/admin/**` | 401 | **404** | 정상 |

프론트의 라우트 가드는 **편의**다. 유일한 방어선은 서버의 404다.
