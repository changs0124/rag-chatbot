# 00_계획 - rag-chatbot

> 이 저장소는 볼트 `10_Dev/Architecture/프로젝트 진행 가이드`(v2.4)의 0-A~8단계를 따름. 이 문서 머리에 **실행 규칙 요약(S-1~S-3)** 과 **게이트 상태**를 심어, 저장소만 보는 사람/세션/CI도 규칙을 볼 수 있게 함.

## 실행 규칙 요약 (가이드 S-1~S-3 발췌)

- **S-1 절대 금지** : 모르는 것을 채우지 않음(모호하면 멈추고 물음) · 확인 안 한 숫자를 판정에 쓰지 않음 · 검증 없이 "완료"라 하지 않음(명령 출력/응답/화면 근거 + 종료 코드 확인) · 버전을 기억으로 답하지 않음(공식 문서 + 확인일) · 기준을 낮춰 통과시키지 않음 · 테스트 skip/게이트 완화 금지 · 스텁/목을 완료로 위장 금지(미결 등재) · 시크릿 비커밋 · 작성과 리뷰를 같은 컨텍스트에서 하지 않음
- **S-2 상시 3** : 완료 판정 없는 항목에 착수 안 함 · 새 테스트는 반드시 한 번 깨뜨려 실패 확인 · 문서와 코드는 같은 커밋/PR에서 움직임
- **S-3 멈추고 물을 것** : 기술 스택 최종 채택 · 플랜 승인 · 비용 발생 · 도메인/계정/시크릿 · 대외 공개 · 법적 문구 · 모호한 요구 · 되돌릴 수 없는 파일 조작 · 승인 범위/AC 변경

## 개요

| 항목 | 값 |
|------|-----|
| 프로젝트명 | rag-chatbot |
| 유형 | 신규 |
| 규모 | 정식 (1주~1개월) |
| 한 줄 목적 | OpenAI GPT-4o + Store(VectorDB) 기반으로 출처를 항상 표기하는 RAG 챗봇 |
| 성공의 정의(상태) | 로그인한 사용자가 텍스트/이미지로 질문하면, 출처가 각주로 달린 답변(자료 없으면 "자료 없음 + 추론" 접두)이 **스트리밍으로** 표시되고, 그 대화가 저장되어 다시 열람됨. API/VectorDB 미구축 상태에서도 **목업 모드로 이 흐름 전체가 동작함** |
| 성공 확인 수단 | 화면(질문→출처 달린 답변 표시) · 응답(API 계약) · 저장 후 재조회 화면 |
| 담당 | changs0124 |
| 착수일 | 2026-07-24 |
| 목표 런칭일 | 미정 (2단계 플랜에서 확정) |
| 참조 구현 | `D:/dev/openai-rag-bot` (강한 참조 원장 - 동일 개념 선행 구현 + 역설계 PLAN v3.0). 유형은 신규 유지, 데이터/인증 계층은 MyBatis+자체로 새로 작성 |

## 포함 범위

| 번호 | 항목 | 이 항목이 없으면 무엇이 성립하지 않는가 |
|------|------|------------------------------------------|
| R-1 | RAG 응답 코어 : 질문 → Store 검색 → 출처 포함 답변 | 챗봇의 존재 이유가 없음 |
| R-2 | 입력 4종 : 텍스트 · 파일 첨부 · 카메라 촬영 · 사진(갤러리) 업로드 | 멀티모달 질문이 불가 |
| R-3 | 첨부 이미지 GPT-4o 비전 전달 + 대화에 저장 | 사진 기반 질문이 처리되지 않고 이력에도 안 남음 |
| R-4 | 출처 표기(각주 번호 + 하단 출처 목록) · 무자료 시 "자료 없음 + 추론" 접두 | 신뢰성(R 핵심 요구) 미충족 |
| R-5 | 사용자 인증 : 자체 이메일/비밀번호 로그인 | 사용자별 대화/마이페이지가 불가 |
| R-6 | 마이페이지 : 이름 변경 · 비밀번호 변경 · 테마 변경(라이트/다크/시스템) | 개인화가 불가 |
| R-7 | 사용자별 대화 저장/조회 | 대화 이력 유지가 불가 |
| R-8 | 반응형 웹 UI (Claude/GPT 류 채팅 틀, Supernova로 마감) - PC + 모바일 브라우저 | PC/모바일 사용이 불가 |
| R-9 | 응답 스트리밍(타이핑 효과) | 응답 대기 UX가 저하됨 |
| R-10 | 목업 계층 : `APP_MODE=mock`, 실 연동 인터페이스는 완성 · 응답만 목 데이터 | API KEY/VectorDB 없이 개발·시연이 불가 |
