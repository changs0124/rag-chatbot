## 탈락 표

| 후보 | 무효화 사유 | 전제가 바뀌어도 성립? |
|------|-------------|------------------------|
| Spring Boot 4.1.0 | MyBatis SB4 스타터(4.1.0)가 2026-07-16 릴리스로 안정성 검증이 얕고, 참조 구현과 라인이 달라 초기 리스크가 큼. EOL 보안 공백은 목업/개발 단계라 트레이드오프로 수용 | **아니오(시간 의존)** - 성숙하면 사유 소멸. 그래서 두 안을 사용자에게 제시해 3.5.16을 택했고, **"SB4 업그레이드 재검토"를 미결 표에 등재**함 |
| MySQL / MariaDB | uuid 네이티브 타입 미지원(CHAR(36)/BINARY(16) 우회) + 참조 구현 Postgres 스키마와 불일치로 이식 비용 발생 | 예 - uuid/jsonb 활용과 참조 정합성은 오래가는 기준 |
| 공식 openai-java SDK 4.45.0 | Vector Stores API가 아직 `OpenAI-Beta` 헤더를 요구(완전 GA 미확인)하고, SDK 마이너 업데이트마다 시그니처 변화 위험. 참조 검증 패턴(RestClient) 미활용 | **아니오(부분/시간 의존)** - SDK가 GA로 안정화되면 유리. **2차 폴백으로 유지**하고 미결 표에 전환 트리거 등재 |
| 서버 세션(쿠키) | SSE `fetch`·모바일·수평 확장에서 stateless JWT가 유리. 상태 저장소 불필요 | 예 - stateless 요구는 오래감 |
| EventSource(SSE 표준 API) | Authorization 헤더·POST 불가라 JWT 인증과 구조적으로 불일치 | 예 - 인증 헤더 필요성은 오래감 |
| Tailwind CDN 방식 | 실앱 번들의 공식 권장 경로가 아님(플러그인 방식). CDN은 Supernova 디자인 시안 산출용 | 예 - 빌드 파이프라인 표준은 오래감 |

> **탈락 사유가 "아니오(시간 의존)"인 2건**(SB4.1.0 · 공식 SDK)은 가이드 통과 조건상 그대로 두면 안 되므로, **미결 표에 "재검토 트리거"로 등재**해 처리함. 두 안 모두 사용자에게 제시 후 현 채택안을 승인받음.

## 플랜 리뷰 기록 (3단계)

- 리뷰 담당 : **critic 서브에이전트(별도 패스)** - 작성 세션과 분리(S-1 자기 승인 금지 충족)
- 리뷰일 : 2026-07-24
- 판정 : **REVISE** (착수 막는 치명 결함 0건, 결정 변경 소견 다수)
- 지적 계수 : **결정 변경 10건**(M1~M9 + m4) · **표현 다듬기 4건**(m1~m3·m5) · **스파이크 추가 5건**
- 처리 결과(라운드 1, 전건 반영) :
  o M1 `OpenAiService` 시그니처 → Phase 4 착수 게이트 + 스파이크 등재
  o M2 실 응답 스키마 → 실키 대기 스파이크(미결 등재)
  o M3 RestClient SSE 증분 → 스파이크 등재(참조가 RestClient+수동 파싱 사용 확인이 완화 근거)
  o M4 무자료 판정 → Phase 4 산출물에 규칙 + Mock 무자료 트리거, AC-6 보강
  o M5 문서 RAG 수명주기 → Phase 4 수명주기 호출 + R-11 + AC-12
  o M6 이미지 서빙 인증 → Phase 3 서명 경로 토큰, AC-22 + R-10 + 스파이크
  o M7 uuid 왕복 → Phase 1 스파이크, AC-20 보강
  o M8 Phase 6 과대 → 6a~6d PR 분해
  o M9 R-6·R-9 테스트명 → R-9 `OpenAiServiceBoundaryTest`, R-6는 미결 이관, R-10~12 신설
  o m4 이미지 단독 전송 → AC-21
  o m1 이관-1 문구 · m2 운영 프로필(Phase 0) · m3 JWT 시크릿(`.env.example`) · m5 SB EOL 런칭 전 재검토(미결) 반영
- 재리뷰(라운드 2) : **APPROVE** - 14건 전건 닫힘, 새 결정 변경 0건. 잔여 문구 3건(스파이크 라벨·AC-22 404·AC-21 검증 위치) 정리 완료. 참조 구현이 실제 `RestClient`+`BufferedReader` 수동 파싱을 씀이 코드로 확정(M3 완화·탈락 사유 사실 검증)
- 라운드별 결정 변경 카운트 : 라운드1=10 → 라운드2=0. 잔여는 순수 문구라 실질 통과. 잔여 스파이크는 착수 시점(Phase 0~5) 게이트로 처리됨
