> 이 문서의 대상이다.

## 0. 지금 상태를 정확히 적는다

`backend/src/main/java/com/ragchatbot/openai/OpenAiRealService.java` 는 **컴파일과 구조만 검증된 상태**다.
클래스 주석이 스스로 밝히고 있듯 실 응답과 대조한 적이 없다. 따라서 이 문서는 "설정만 넣으면 된다"가 아니라
**"설정을 넣은 뒤 무엇이 어긋날 수 있는지"** 를 함께 적는다.

검증되지 않은 가정은 3절에 전부 나열한다. 하나라도 어긋나면 증상이 다르게 나타나므로, 원인을 찾는 데
쓰는 시간을 줄이려면 그 목록을 먼저 훑는 편이 빠르다.

## 1. 준비물

| 준비물 | 환경변수 | 없으면 생기는 일 |
|--------|----------|------------------|
| OpenAI API 키 | `OPENAI_API_KEY` | `APP_MODE=live` 기동 즉시 실패(fail-fast). per-request 401로 흐르지 않는다 |
| 공용 Vector Store ID | `OPENAI_VECTOR_STORE_ID` | 기동·응답은 되지만 `file_search` 툴을 아예 붙이지 않아 **출처가 항상 0건**이 된다 |
| 모델 이름 | `OPENAI_MODEL` | 미지정 시 `gpt-4o`. 비전 입력을 쓰므로 **이미지 지원 모델이어야 한다** |
| 실행 모드 | `APP_MODE=live` | 미설정이면 `AppModeGuard`가 기동을 막는다(의도된 설계) |

전량은 `backend/.env.example` 에 이름만 적혀 있다. 값은 저장소에 넣지 않는다.

## 2. 투입 절차

각 단계는 **다음 단계로 넘어가기 전에 확인할 것**을 함께 적는다. 확인 없이 다음으로 넘어가면
실패했을 때 어느 단계가 원인인지 분리되지 않는다.

### 2-1. Vector Store를 만들고 문서 1건만 넣는다

처음부터 전량을 올리지 않는다. **문서 1건**이면 3절의 가정이 전부 드러난다.

- 확인 : Vector Store의 파일 상태가 `completed` 인지 본다. `in_progress` 로 멈춰 있으면 파싱 단계에서
  막힌 것이라 아래 단계가 전부 무의미하다.

### 2-2. 백엔드를 `APP_MODE=live` 로 띄운다

- 확인 : 기동이 성공한다. 키가 비면 여기서 즉시 실패하므로, 기동됐다는 것 자체가 키 주입 성공의 근거다.

### 2-3. 2-1에서 넣은 문서의 내용을 묻는다

- 확인 ① : 답변 토큰이 **흘러서** 온다(한 번에 뭉쳐 오지 않는다). 뭉쳐 오면 스트리밍이 아니라
  버퍼링된 것이므로 `RestClient` 응답 처리를 봐야 한다.
- 확인 ② : 진행 단계에 **「참조 문서 검색 중」** 이 뜬다. 안 뜨면 `file_search` 호출 이벤트가
  도착하지 않은 것이다(3절 가정 A).
- 확인 ③ : 답변 하단에 **출처 각주가 뜬다**. 각주가 없고 「자료 없음」 배너가 뜨면 인용 추출이
  실패한 것이다(3절 가정 B·C).

### 2-4. 자료에 없는 것을 묻는다

- 확인 : 「자료 없음 - 관련 자료를 찾지 못해 추론으로 답변함」 배너가 뜬다. 2-3과 2-4가 **모두**
  기대대로 나와야 무자료 판정이 동작하는 것이다. 한쪽만 보면 "항상 0건"과 구분되지 않는다.

### 2-5. 이미지를 첨부해 묻는다

- 확인 : 이미지 내용을 반영한 답변이 온다. `OPENAI_MODEL` 을 비전 미지원 모델로 바꿨다면 여기서 드러난다.

### 2-6. 전량 업로드

2-1~2-5가 전부 통과한 뒤에 문서를 전량 올린다. 이 시점부터는 저장 용량 과금이 시작된다.

## 3. 실 응답과 대조해야 하는 가정

아래는 **문서만 보고 작성돼 실물로 확인된 적이 없는** 값들이다. 2-3에서 기대와 다른 결과가 나오면
여기부터 본다.

| ID | 가정 | 어긋나면 나타나는 증상 |
|----|------|------------------------|
| A | 검색 시작 이벤트 이름이 `response.file_search_call.in_progress` 또는 `response.file_search_call.searching` | 「참조 문서 검색 중」 단계가 화면에 뜨지 않는다. 답변은 정상 |
| B | 완료 이벤트 이름이 `response.completed` | **스트림이 완료 없이 끝났다**는 오류로 끝난다. 조용히 무자료로 넘어가지 않도록 일부러 던지게 해 둔 경로다 |
| C | 인용 annotation의 타입이 `file_citation` 이고 파일명 필드가 `filename` | 답변은 정상인데 출처가 늘 0건이라 **모든 답변에 「자료 없음」 배너**가 붙는다 |
| D | 검색 결과 본문이 `file_search_call` 항목의 `results[].text` 에 실린다 | 출처 각주는 뜨는데 스니펫이 빈칸이다 |
| E | `include: ["file_search_call.results"]` 로 결과 본문을 받을 수 있다 | D와 같은 증상 |

가정 C는 특히 **오진하기 쉽다.** "자료 없음"은 정상 동작으로도 나오는 표시라, 스토어에 문서가 있는데도
0건이면 검색이 안 된 것인지 인용 추출이 깨진 것인지 화면만 봐서는 구분되지 않는다. 2-3에서
**스토어에 확실히 있는 내용**을 물어 구분한다.

## 4. 비용이 발생하는 지점

투입 전에 알고 있어야 하는 과금 요소다. 수치는 2026-08 기준이며 변동한다.

| 항목 | 과금 방식 | 비고 |
|------|-----------|------|
| 벡터 저장 | 1GB 무료, 초과분 일 단위 | **원본 파일 크기가 아니라** 파싱된 청크 + 임베딩 합계 기준이다. 텍스트 위주 문서는 기본 청킹(800토큰/400오버랩)에서 원본보다 커진다 |
| 검색 툴 호출 | 호출 건수 | 대화 턴마다 1회 붙는다 |
| 토큰 | 입력·출력 | 검색된 청크가 입력에 실려 들어간다 |
| 이미지 | 입력 토큰 | 첨부 이미지를 base64로 인라인한다. 과거 턴은 재전송하지 않는다 |

**계획 단계에서 먼저 잴 것** : 대표 문서 몇 건을 올려 Vector Store의 실측 크기와 원본 크기의 비율을
확인한다. 이 배율 하나가 월 비용을 한 자릿수 배 가른다. 추정으로 계산하지 않는다.

토큰 사용량을 저장에 남기는 작업은 `docs/99_inbox/05-features.md` 의 FEAT-OPS-001에서 다룬다.
그것이 들어가기 전에는 **앱 안에서 사용량을 볼 수단이 없다.**

## 5. 문서를 넣는 경로

현재 `backend/src/main/java/com/ragchatbot/service/FileService.java` 는 이미지만 받고 PDF는 400으로
거절한다. 이는 의도된 계약이다 — 문서 첨부가 모델에 전달되지 않는데도 업로드되어 "그 PDF를 근거로
답했다"는 오해를 만들었기 때문이다.

따라서 **공용 Vector Store에 문서를 넣는 경로는 현재 제품 안에 없다.** 2-1과 2-6은 OpenAI 대시보드에서
수동으로 해야 한다.

이 절차를 제품 안으로 들이는 작업은 `docs/99_inbox/05-features.md` 에서 다룬다. 그 전까지는
누가 언제 어떤 문서를 올렸는지 저장소에 기록이 남지 않는다는 점을 감수한다.

## 6. 되돌리기

문제가 생기면 `APP_MODE=mock` 으로 되돌린다. 목업은 실 키 없이 전 경로가 동작하므로,
서비스를 세우지 않고도 원인을 찾을 시간을 벌 수 있다.
