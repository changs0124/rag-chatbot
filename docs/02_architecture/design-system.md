# 디자인 시스템

> **목표** — 색은 **회사 CI(디인사이트)에서 파생**시키고, 레이아웃 구조는 ChatGPT · Claude 채팅 앱을
> 따른다. 모바일까지 함께 정한다. 랜딩페이지 전제 규칙은 골라서 버린다(§6).
>
> **색은 로고 안에 실재하는 값에서만 나온다** — 지어낸 파랑을 넣지 않는다. 값은 로고에서 시작해 대비까지 맞춘 회사 홈페이지
> (dinsight.kr, `dinsight-renew`)의 체계를 그대로 가져오며, 아래 토큰 표의 출처 열이 그 대응이다.

## 1. 색 — 토큰으로만 쓴다

**화면은 라이트 하나다**(#191). 다크·시스템 테마는 없다 — OS 가 다크여도 이 값으로 뜬다(`color-scheme: light`).

쿨 뉴트럴 계열이다. 바탕을 순백으로 두지 않는다 — 대화가 길어지는 화면에서 순백은 눈이 빨리 지친다.
홈페이지와 같은 원칙을 따른다 — **면은 무채색이고, 브랜드 시안은 버튼·링크·활성 표시에만 쓴다.**

### 브랜드 원색과 그 한계

로고에서 뽑은 값은 셋이다. **그중 둘은 글자·버튼 색으로 쓸 수 없다.**

| 로고 값 | 자리 | 흰 글자 대비 | 판정 |
|---------|------|--------------|------|
| `#41BAE9` | D 마크 본체 | 2.2:1 | 버튼색 불가. 로고(`Logo.tsx`)에만 쓴다 |
| `#F2931D` | 좌하단 블록 | 2.3:1 | 밝은 면 위 글자색 불가. 로고(`Logo.tsx`)에만 쓴다 |
| `#0070B5` | D 마크 접힘면 그라데이션의 가장 어두운 지점 | 5.3:1 | 로고 램프(`Logo.tsx`)에만 쓴다 |

`accent` 는 홈페이지의 `--brand-deep`(`#08719B`)이다. 홈페이지 브랜드 원색 `#43BAE8`(로고 시안과 같은
색상각)의 **명도만 내린 값**이라 흰 글자 5.46 을 번다.
오렌지는 화면 토큰에 없고(`highlight` 는 무채색 — 홈페이지 칩·배지가 무채색이다) 로고 블록에만 남는다.

**합성값**(`line` · `accent-soft`)은 홈페이지가 투명도로 쓰는 색을 흰 바탕 위에 미리 섞은 것이다 — 앱은 토큰을 불투명 hex 로
두므로 그대로 옮길 수 없다. 서체(홈페이지 Wanted Sans)는 #190 · #646 모두 범위 밖이다(Pretendard 유지).
조판은 #646 에서 정했다(§3 · §5) — 카드는 1px `line` 경계 + 한 겹 그림자, 이중 테두리는 걷었다.

### 토큰 밖 겹침 — 실측 (#155)

반투명을 겹치면 실제 바탕이 토큰 값이 아니게 된다. 그 자리는 위 표가 못 덮으므로 따로 잰다.
**아래 면이 여럿이면 최악값**을 적는다(오버레이는 `canvas`·`surface`·`raised` 중 최악,
첨부 실패 패널은 임의 이미지 중 최악인 흰 이미지).

| 자리 | 조합 | 대비 | 기준 |
|------|------|--------|------|
| 드롭 오버레이 글자 | `text-ink` / `bg-canvas/85` | 12.67 | 4.5 |
| 드롭 오버레이 점선 | `border-accent` / `bg-canvas/85` | 5.23 | 3.0 |
| 첨부 실패 아이콘 | `text-highlight` / `bg-black/75` + 이미지 | 8.34 | 3.0 |

첨부 실패 패널은 **화면 색과 무관한 고정 어두운 면**이다. 그래서 **여기에는 밝은 면 기준 토큰을 쓸 수 없다** —
`danger` 를 쓰면 `#C0392B` 가 어두운 패널에 얹혀 **1.91** 이 된다(흰 이미지 위 `black/75` 기준 — 1.06 은 스크림이 `black/60` 이던 때 값).

스크림은 `bg-black/75` 다 — 아이콘이 비텍스트 기준 3.0 을 넘어야 한다(스크림 농도별 실측은 CHANGELOG #155).

### 이 표가 덮지 못하는 것

**"토큰 쌍"이라고 쓴 것은 한정이다.** 화면에는 토큰끼리 만나지 않는 조합이 남아 있고,
그건 위 계산에 들어가지 않는다. 바로 위 「토큰 밖 겹침」 셋은 재 놓았다. 남아 있던 입력칸 테두리 미달(`line` / `canvas` 1.48)은
#646 에서 입력칸만 `line-strong`(3.32 · 3.24)으로 올려 풀었다 — 장식선 `line` 은 그대로라 입력칸에 쓰지 않는다(§5). 지금 이 절에 남은 미달은 없다.

**대비 주장을 검사하는 게이트는 없다.** `check-doc-versions.sh` 가 버전 주장을 지키는 것과 달리
대비 주장은 아무도 안 본다 — 색을 건드리면 이 표를 손으로 다시 재야 한다.

### 쓰는 방법 (중요)

토큰은 `index.css` 의 `:root` 에 CSS 변수로 두고, Tailwind 4 의 `@theme` 이 그 변수를 가리키게 한다.
**`dark:` · `data-theme` · `prefers-color-scheme` 을 쓰지 않는다** — Tailwind 4 의 기본 `dark:` 는 OS 미디어쿼리라,
쓰면 OS 가 다크인 사용자에게만 화면이 갈린다(`src/theme-tokens.test.ts` 가 막는다).

```
bg-canvas · bg-surface · bg-raised · from-canvas
text-ink · text-ink-muted · bg-ink-muted · border-line · divide-line · border-line-strong
bg-accent · bg-accent-hover · text-accent · text-accent-ink · bg-accent-soft · border-accent · outline-accent
bg-highlight · text-highlight · text-highlight-ink
bg-danger · text-danger · text-danger-ink · bg-danger-soft · border-danger
```

25종이 실제로 쓰인다(11-10 #658 에서 다시 셈). **토큰 16개가 전부 쓰이고, 쓰는데 정의 안 된 것은 없다.**
(`TextInput` · `Composer` · 대화 제목 편집의 포커스 링은 유틸리티가 아니라 `var(--c-focus-ring)` 을 직접 참조한다)

### 포커스 — 홈페이지 규칙 그대로 (#190)

| 자리 | 표시 | 홈페이지 대응 |
|------|------|---------------|
| 입력칸(`TextInput` · `Composer` · 대화 제목 편집) | 테두리 `accent` + 바깥 링 4px `--c-focus-ring` | `.field` 의 `focus:border-primary-deep focus:ring-4 focus:ring-primary/15` |
| 버튼 · 링크 등 나머지 | 키보드 포커스(`:focus-visible`)에 2px `accent` 외곽선, 2px 띄움 | `.rule-row-link:focus-visible` 의 `outline-2 outline-primary-deep` |

`--c-focus-ring` 은 `rgb(67 186 232 / 0.15)` — 토큰 16개와 달리 **투명도를 그대로 둔** 변수다. 링은 아래 면 위에 얹히므로
불투명으로 섞어 두면 면에 따라 색이 어긋난다. `@theme` 에 올리지 않아 `bg-…` 유틸리티로는 쓸 수 없다(쓸 자리가 링뿐이다).

전역 `:focus-visible` 규칙은
`@layer base` 안에 둔다 — 레이어 밖이면 `outline-none` 유틸리티보다 강해져 자체 포커스 표시가 있는 입력칸에 외곽선이 겹친다.
외곽선 `#08719B` 는 바탕(`canvas`)에서 5.32, 사이드바(`surface`)에서 4.85 로 비텍스트 기준 3.0 을 넘는다.

**토큰을 만들면 쓰는 자리를 함께 정한다.** 쓰임이 적은 4종의 자리는 이렇다.

| 토큰 | 자리 | 사용 |
|------|------|------|
| `highlight` · `highlight-ink` | 배지 : `chat/MessageList.tsx` 「자료 없음」 · `AdminDocumentsPage` 처리중 · `AdminUsersPage` 사용자 역할(#646) | 같은 짝으로만 쓴다(대비 표 10.63) |
| `highlight` | `chat/Composer.tsx` 첨부 실패 아이콘 | 1회. 어두운 고정 스크림 위라 밝은 면 기준 토큰을 못 쓴다 |
| `highlight` | 스켈레톤 막대 : `ChatPage` 이력 로딩 · `AdminListSkeleton`(#646) · 사이드바 첫 목록(#663) | 글자 없는 자리 표시라 대비 기준이 없다 |
| `danger-ink` | `ConfirmModal.tsx` 확인 버튼(삭제 · 비밀번호 초기화) | 1회 — `bg-danger` 가 있는 유일한 자리다 |
| `danger-soft` | `components/AdminErrorBanners.tsx` 관리자 오류 배너 | 1회 — 관리자 두 화면이 공용으로 쓴다(#541) |
| `danger-soft` | `pages/MyPage.tsx` 오류 배너 | 1회. 관리자 쪽과 같은 색 조합(모서리 · 여백은 다르다) |
| `danger-soft` | `AdminDocumentsPage` 실패 배지(#646) | `danger` 글자와 짝(4.64) |

쓰이지 않는 토큰은 다음 사람이 아무 데나 갖다 쓰는 근거가 된다.

## 2. 타이포

- **본문 서체** : Pretendard Variable (npm 패키지로 번들에 넣는다 — CDN 을 새로 물리지 않는다).
  받지 못하는 환경을 위해 시스템 스택을 뒤에 둔다.
- **금지** : `Noto Sans KR` · `Malgun Gothic` 을 **선순위로** 지정하지 않는다. 자소 간격이 넓어 화면이 헐거워 보인다.
- **크기(타입 스케일, #646)** — 단계를 줄여 화면마다 같은 자리는 같은 크기다.

  | 자리 | 크기 · 굵기 |
  |------|-------------|
  | 화면 제목(설정 · 문서 관리 · 사용자 관리) | 20px → md 24px(`text-xl md:text-2xl`) · semibold · `tracking-tight` |
  | 빈 채팅 인사 | 24px → md 28px · semibold · `tracking-tight` |
  | 로그인 소개 제목 | 24px → md 36px(`text-2xl md:text-4xl`) |
  | 구역 제목(카드 · 목록 머리) | 16px(`text-base`) semibold |
  | 본문 · 답변 | 15px |
  | 목록 행 이름 · 버튼 · 보조 글 | 14px(`text-sm`), 행 이름은 medium |
  | 보조 버튼 · 폼 라벨 | 13px medium |
  | 메타 · 배지 · 사이드바 묶음 이름 | 12px(`text-xs`) — **한글에는 `uppercase` · 자간(`tracking-[…]`)을 쓰지 않는다**(효과가 없고 글자만 벌어진다). 역할 배지 · 파일 종류 타일만 11 · 10px |

  **답변 문단**은 14px 보다 작게 두지 않는다
  (`Markdown.tsx` 의 코드 블록 13px · 표 14px 는 이 규칙 밖이다).
- **한국어 규칙**
  - `body` 에 전역 `word-break: keep-all`(`index.css`), 한국어 블록에는 `break-keep` 도 — 조사 앞에서 줄이 갈리면 읽는 속도가 눈에 띄게 떨어진다
  - 본문 `leading-relaxed`, 제목 `leading-snug`. 한국어는 라틴보다 행간이 더 필요하다

### 그림자는 세 단계다

깊이를 섞으면 같은 층위의 것들이 다른 높이로 보인다. **면 위에 얹힌 것과 화면 위에 뜬 것을 나눈다.**

| 토큰 | 값 | 쓰는 곳 |
|------|-----|---------|
| `--shadow-card` | `0 1px 2px rgb(16 24 40 / .06)` | 1px 경계가 있는 카드 · 목록 묶음 · 「새 대화」 버튼 · 지금 대화 행(#646) — 경계가 모양을 맡고 이것은 바닥에 붙은 느낌만 낸다 |
| `--shadow-ambient` | `0 1px 2px rgb(0 0 0 / .04), 0 8px 24px -12px rgb(0 0 0 / .1)` | 채팅 입력창 · 로그인 카드 · 첨부 제거 원 |
| `--shadow-lifted` | `0 2px 4px rgb(0 0 0 / .05), 0 16px 40px -16px rgb(0 0 0 / .18)` | **화면 위에 뜬 것** — 모달(`ConfirmModal` · `AdminUsersPage` 발급 창) · 드로어(`ChatPage`) · 팝오버(`Sidebar`) |

모달에 `ambient` 를 쓰면 기존 모달과 깊이가 갈린다.

## 4. 모션

- **이징 한 가지** : `cubic-bezier(0.16, 1, 0.3, 1)` — `--ease-out-quint` 로 두고 전 컴포넌트가 쓴다.
  `linear` · `ease-in-out` 금지.
- **지속** : 150ms 하나(`duration-150`) — 상태 변화 · 모달 모두
- **속성** : `transform` · `opacity` · 색(`transition-colors`) · 입력 포커스 테두리(`border-color` · `box-shadow`)만. 레이아웃을 흔드는 속성(폭 · 높이 · 여백)에 트랜지션을 걸지 않는다
- **누르는 느낌은 색으로 낸다**(#646) — hover 는 면 색만 바꾼다(주요 `accent-hover`, 보조 `surface`, 위험 `brightness-95`).
  예전의 `hover:scale-[1.02]` / `active:scale-[0.98]` 는 걷었다 — 버튼 · 카드가 커졌다 줄었다 하면 장난감처럼 읽힌다(사용자 평가 「처음 만든 디자인 같다」)
- **로딩은 자리 모양으로 보인다**(#646) — 돌아가는 원 대신 올 내용의 모양(스켈레톤, `animate-pulse` + `bg-highlight`)을 깐다. 답변 준비 중은 점 셋(`animate-bounce`)과 단계 글자.
  둘 다 `motion-reduce:animate-none`. 예외 : 자리 모양이 없는 짧은 작업 — 첨부 업로드 중 카드 위 회전 원 · 「스토어와 동기화」 아이콘 회전은 그대로다(전역 reduced-motion 규칙이 1ms 로 멈춘다)
- **끄는 중에는 트랜지션을 끈다** : 사이드바 폭 드래그처럼 값이 매 프레임 바뀌는 동작에 트랜지션이 걸리면
  손가락보다 늦게 따라와 고무줄처럼 보인다
- **`prefers-reduced-motion: reduce` 를 존중한다** : 모든 트랜지션·애니메이션을 1ms 로 줄인다. JS 로 굴리는 스크롤(`scrollIntoView`)은 CSS 로 꺼지지 않으므로 설정을 읽어 `smooth` 를 쓰지 않는다(#644)

## 5. 컴포넌트 규칙

- **말풍선은 사용자 쪽에만 둔다.** ChatGPT · Claude 모두 답변에는 배경을 깔지 않는다 —
  답변이 길 때 큰 색면이 화면을 갈라 읽기 흐름을 끊는다. 사용자 메시지만 그림자 없는 `surface` 말풍선(`rounded-3xl`)으로 오른쪽 정렬한다(#646 — 떠 있는 카드보다 가라앉은 면이 시선을 답변 쪽으로 넘긴다).
- **입력창은 떠 있는 판이다.** `raised` + 확산 그림자 + `rounded-3xl` + `line-strong` 테두리. 포커스면 테두리가 `accent` 로 바뀌고 시안 15% 링이 4px 둘린다(#190).
  입력줄은 내용만큼 자라고 상한에서 안쪽 스크롤로 바뀐다 — 모바일 128px · md 160px(가상 키보드가 열리면 대화 칸이 좁아져 모바일을 낮춘다, #643). 한 줄 높이는 버튼과 같은 44/40px.
  **입력칸(채팅 입력창 · 폼 · 제목 수정)의 테두리는 `line-strong`**(#646) — 장식선 `line` 은 1.52:1 이라 경계가 안 보인다. 입력칸은 `surface` 위에 두지 않는다(2.95:1) — 폼은 흰 카드 안에
- **스크롤 페이드** : 메시지 영역 하단에 `canvas` 로 가는 그라데이션을 깔아 입력창 뒤로 글이 사라지게 한다.
- **활성 대화**(#646) : `raised` 면 + `ink` medium 글자 + 한 겹 그림자 + **왼쪽 3px `accent` 막대**. 예전의 `accent-soft` 배경은 사이드바 면과 1.03:1 이라
  색 하나(글자색)로만 구분됐다(WCAG 1.4.1). 굵기와 막대가 색 말고도 드러낸다. 낭독기에는 `aria-current`(#590)
- **사이드바 폭** : `ResizableSidebar` 가 관장한다(200~420px, 기본 260px, `localStorage`). 범위 밖 저장값은 무시하고 기본값으로 연다.
  손잡이는 `role="separator"` 로 키보드에서도 조절된다. 모바일 드로어에는 손잡이가 없다.
- **버튼 체계(#646)** — 모양은 넷이다. 글자 버튼(주요 · 보조 · 위험)의 반경은 모두 `rounded-lg` 다.

  | 종류 | 모양 | 정본 |
  |------|------|------|
  | 주요 | `accent` 면 · 흰 글자 · hover `accent-hover` · `h-11`(44px) | `components/primaryButton.ts` 의 `primaryButtonClass`(#330). 로그인은 `h-12` 전폭이라 따로 |
  | 보조 | `raised` 면 + 1px `line` 경계 · `ink` 13px medium · hover `surface` · 모바일 `min-h-11` / 데스크톱 `h-8` | `components/actionButton.ts` 의 `actionButtonClass` — 관리 목록 행 끝(동기화 · 초기화 · 삭제). 삭제는 hover 에 `danger` 글자 · 경계 |
  | 위험 | `danger` 면 · 흰 글자 · hover `brightness-95` · `h-11 md:h-10` | 확인 모달의 확정 버튼 |
  | 아이콘 | 투명 면 · hover `surface`(보내기는 `accent` 면 · hover `accent-hover`). 반경은 자리마다 : 입력창 안 + · 보내기 · 중단과 확대 보기 이전/다음은 `rounded-full`, 채팅 헤더 · 뒤로가기는 `rounded-xl`, 확대 보기 내려받기 · 닫기는 `rounded-lg`, 대화 삭제 ✕ · 첨부 재시도는 `rounded-md` | 위 각 컴포넌트 |

  호출부는 바깥 여백 · 폭만 덧붙인다. 설정 · 관리자 상단의 뒤로가기와 페이지 골격은 `BackLink` · `PageShell` 이 가진다.
  화면 이름은 「설정」 하나다 — 메뉴 · 제목 · 관리 화면 뒤로가기가 같은 말을 쓴다(#646)
- **이중 테두리(double-bezel)는 쓰지 않는다**(#646) — 모달 · 로그인 폼도 한 겹 카드(`raised` + 1px `line` + 그림자)다. 바깥 트레이가 카드를 두 번 감싸 무거워 보였다.
- **목록(관리 화면)** — 한 장의 카드(`rounded-xl` + `line` 경계 + `shadow-card`) 안에 행을 `divide-line` 으로 나눈다. 행마다 회색 알약을 쌓지 않는다.
  행 머리에 타일(문서는 확장자, 사용자는 이름 첫 글자), 이름 14px medium, 메타 12px. 모바일에서 버튼이 한 줄에 안 들어가면 아래 줄로 내린다
- **배지** — `rounded-full` · 11~12px medium · 면 + 글자 짝은 토큰 대비 표의 쌍만 쓴다 : 완료 · 관리자 `accent-soft`/`accent`, 처리중 · 사용자 `highlight`/`highlight-ink`, 실패 `danger-soft`/`danger`. 아이콘은 보조(`aria-hidden`)
- **로딩 · 빈 상태 · 오류** — 첫 로드는 스켈레톤(대화 이력 : 질문 말풍선 + 답변 줄, 관리 목록 : `AdminListSkeleton` 행, 사이드바 대화 목록 : 묶음 라벨 + 대화 행 — #663), 실패하면 스켈레톤을 걷고 오류 배너만 남긴다(멈춘 로딩으로 읽히지 않게).
  빈 상태는 카드 안에 「무엇이 없는지 + 무엇을 하면 되는지」 두 문장. 사이드바의 「대화가 없습니다」는 첫 목록이 와서 비었을 때만 보인다 — 오기 전에 보이면 대화가 있는 사용자에게 잠깐 「없다」고 말한다(#663, `useChat` 의 `conversationsLoading`)
- **아이콘** : 지금의 자체 SVG 세트(`frontend/src/components/icons.tsx`)를 계속 쓴다. 굵기 1.8 유지.
  **이모지·장식 기호(📄 ⚠ ● ← → 등)를 화면에 쓰지 않는다**(#192) — 글꼴·OS 마다 모양이 다르고 일부는 컬러 이모지로 떠서
  무채색 화면에서 혼자 튄다. 필요한 모양은 같은 규약(24 격자 · 1.8 stroke · `currentColor`)으로 `icons.tsx` 에 더한다.
  아이콘은 뜻을 혼자 전하지 않는다 — 옆 글자를 남기고 아이콘은 `aria-hidden`(Svg 기본값).
  `src/no-emoji.test.ts` 가 화면 코드(주석 제외)를 훑어 막는다.
- **접근성 규칙(#484)** : 오류 문구는 `role="alert"`(조건부로 삽입해도 낭독된다), 성공 알림은 `role="status"` 를 **늘 렌더하는 그릇**에 글만 바꿔 넣는다(조건부로 삽입하면 낭독되지 않는다. 자리를 늘 비워 두는 문구는 `aria-live`). 입력은 placeholder 만으로 두지 않고 `<label>` 이나 `aria-label` 을 단다.
  같은 이름의 컨트롤이 줄지어 있으면 몇 번째인지 이름에 붙이고(첨부 썸네일), 색으로만 드러낸 현재 항목에는 `aria-current` 를 단다(#590).
  `role="dialog"` 는 `aria-labelledby`(`useId`)로 제목에 잇고, **확인 모달의 첫 포커스는 파괴 버튼이 아니라 「취소」** 다. 호버로만 드러나는 버튼은 `focus-visible` · `group-focus-within` 에서도 드러낸다.
  **모달 · 드로어는 `hooks/useModalFocus` 를 부른다(#644)** — 열린 동안 바깥에 `inert`(Tab · 낭독기 훑기가 뒤 화면에 닿지 않음), 닫히면 연 요소로 포커스 복귀. 모달 틀은 공통화하지 않는다(#105 판정). 숨긴 파일 입력은 `hidden` 이 아니라 `sr-only` 로 둬 Tab 으로 닿게 하고 포커스 표시는 감싼 상자에 준다.
  답이 흐르는 동안 `role="log"` 는 `aria-busy` 로 둬 토큰 조각마다 낭독되지 않게 한다.

## 7-1. 모바일

- 높이는 **`100dvh`** — 규칙과 이유는 [frontend.md](./frontend.md) 「화면 골격」
- 입력창 하단에 `env(safe-area-inset-bottom)` 만큼 여백을 준다(홈 인디케이터 겹침 방지)
- 터치 대상은 최소 44×44px. 헤더 아이콘 버튼·입력 필드·주요 버튼이 모두 이 높이를 지킨다.
  **모바일(md 미만)에서만 키우고 데스크톱 값은 `md:` 로 그대로 둔다** — 마우스는 작은 대상을 정확히 누르고, 데스크톱 밀도를 바꿀 이유가 없다
- 시각 크기를 키우지 않고 누르는 영역만 넓힐 때는 패딩으로 한다(예 : 대화 삭제 ✕ 는 아이콘 16 + `p-3.5`).
  글자 링크(뒤로가기)는 `h-11` 에 `-ml-2 px-2` 로 글자 위치를 유지한다
- **설정·관리자 상단은 채팅 헤더와 같은 높이다** — 위 여백 `pt-2` + 44px 뒤로가기 = 채팅 헤더 `min-h-14` 의 버튼 줄과 같다
- **로그인은 한 겹 카드다**(#646) — 이중 테두리를 걷어(§5) 모바일도 데스크톱과 같은 카드(`px-5 py-7`, 페이지 `px-4`)다.
  모바일은 위에서부터 쌓는다(`content-start pt-12`) — 세로 가운데 정렬은 소개글과 폼 사이에 230px 빈 띠를 만들었다
- **누르는 영역만 넓히는 작은 원** — 첨부 제거(보이는 원 20px)는 `::after` 로 누르는 영역을 넓힌다 : 모바일 30px · 데스크톱 28px(WCAG 2.5.8 24px 이상). 원이 카드 밖으로 6px 나와 있어 영역이 카드 간격(12px)을 넘으면 이웃 카드의 「확대」와 겹친다 — 모바일 36px 은 2px 겹쳐 30px 로 줄였다(#657).
  카드 간격(12px) 때문에 44px 까지는 넓히지 않는다 — 이웃 카드의 확대 버튼 영역을 덮는다. 메뉴 항목 · 확인 모달 버튼 · 확대 보기 버튼은 모바일 44px · 데스크톱 36~40px
- 측정은 `360x740`(일반) · `360x640`(작은 화면) 두 가지로 한다. 360x640 에서 로그인 버튼이 스크롤 없이 보여야 한다(565px)
- 사이드바는 `md` 미만에서 드로어다. 폭 `min(84vw, 320px)`, 배경은 `backdrop-blur` + 반투명 검정
- 드로어가 열린 동안 뒤 화면은 스크롤되지 않게 잠근다
- 드로어는 `role="dialog"` · `aria-modal` · 이름 「대화 목록」 — 열리면 포커스가 안으로, Esc · 배경 탭으로 닫히고 메뉴 버튼으로 돌아온다(#644). 안의 확인 창이 받은 Esc 는 확인 창만 닫는다

## 7-2. 파비콘 · 앱 아이콘

모티프는 **회사 CI 의 D 마크** 다(#151). v1.0 의 「말풍선 + 문서 + 출처 링크」 자체 제작 아이콘은 버렸다 —
제품을 설명하는 그림보다 회사를 식별하는 표식이 탭에서 할 일을 더 잘한다.

사방에 **12% 여백**을 둔다. 여백 없이 꽉 채우면 32px 로 줄었을 때 가장자리가 타일에 물린다.

**벡터 정본은 `frontend/src/components/Logo.tsx` 의 마크 상수(`MARK` · `ORANGE` · `FOLD_STOPS`)다.** 파비콘 전용 SVG 를
따로 두지 않는다 — 같은 좌표를 두 파일이 들고 있게 되고, 한쪽만 고쳐도 잡아 줄 게이트가 없다.
(#153 에서 실제로 `favicon.svg` 를 커밋해 봤다가 **몇 시간 만에 오렌지 경로가 한 글자 갈라져**
되돌렸다.)

| 파일 | 쓰임 | 배경 |
|------|------|------|
| `docs/02_architecture/assets/favicon-source.png` | 512px 래스터. `Logo.tsx` 의 마크를 렌더한 산출물이고 작은 크기는 여기서 뽑는다 | 투명 |
| `frontend/public/favicon.ico` | 16 · 32 · 48px 묶음 (탭) | 투명 |
| `frontend/public/favicon-32.png` | 32px PNG | 투명 |
| `frontend/public/apple-touch-icon.png` | 180px (iOS 홈 화면) | **흰 타일** |

`favicon-source.png` 는 생성 중간 산물이라 `frontend/public/` 에 두지 않는다 — 거기 있으면
아무도 참조하지 않는 채 빌드 산출물에 실린다. 빌드가 복사하지 않는 이 문서 옆 `assets/` 에 둔다.

### 재생성 절차

`Logo.tsx` 의 마크를 고쳤을 때만 돌린다. **3단계다.**

1. `Logo.tsx` 에서 `MARK` · `ORANGE` · `FOLD_STOPS` 를 읽어 12% 여백을 넣은 512px SVG 문자열을 만든다
2. 브라우저로 512px 렌더 (`omitBackground` 로 투명 유지)
3. Pillow 로 32px · 180px(흰 타일) · ico(16·32·48) 파생

2·3 단계는 이렇다.

```bash
# 2) SVG 문자열 -> 512px PNG
node -e "
const {chromium}=require('playwright'),{readFileSync}=require('fs');
(async()=>{const b=await chromium.launch(),p=await(await b.newContext({viewport:{width:512,height:512}})).newPage();
await p.setContent('<body style=\"margin:0\">'+readFileSync(process.argv[1],'utf8')+'</body>');
await p.screenshot({path:'docs/02_architecture/assets/favicon-source.png',omitBackground:true});await b.close()})()" <svg파일>

# 3) 512px -> 나머지 3종
python -c "
from PIL import Image
s=Image.open('docs/02_architecture/assets/favicon-source.png').convert('RGBA')
s.resize((32,32),Image.LANCZOS).save('frontend/public/favicon-32.png')
t=Image.new('RGBA',(180,180),(255,255,255,255)); t.alpha_composite(s.resize((180,180),Image.LANCZOS))
t.convert('RGB').save('frontend/public/apple-touch-icon.png')
s.save('frontend/public/favicon.ico',sizes=[(16,16),(32,32),(48,48)])"
```

**1단계의 좌표 주의** : 여백을 주려면 마크를 `translate` 안에 넣게 되는데,
`gradientUnits="userSpaceOnUse"` 는 **참조하는 요소(rect)의 좌표계**에서 해석된다.
`x1`/`x2` 에 translate 밖 좌표를 넣으면 접힘면 음영이 그만큼 밀려 **탭의 파비콘과 화면 안 로고가
서로 달라진다.**

**검증** : 돌린 결과가 커밋된 `favicon-source.png` 와 **픽셀 단위로 같아야 한다**
(#153 에서 최대 채널차 0 으로 확인). 다르면 마크를 고쳤거나 렌더러가 바뀐 것이다.

**1단계를 자동화하는 스크립트는 없다.** 마크가 바뀌는 일이 드물어 근거가 한 건뿐이고,
이 저장소는 그럴 때 도구를 만들지 않는다(#55 · #149 기준). 필요해지면 그때 만든다.

`apple-touch-icon` 만 흰 타일을 까는 이유 : iOS 는 투명을 검게 메워 버려서, 투명으로 두면
홈 화면에서 검은 사각형 위에 마크가 앉는다.

`frontend/index.html` 이 png · ico 를 가리키고, 주소창 색(`theme-color`)은 `canvas` 값과 같다.
**`<meta>` 는 하나뿐이고 값은 고정이다** — 화면이 라이트 하나라 따라갈 상태가 없다. 미디어쿼리로 두지 않는다 — OS 가 다크면 주소창만 다크가 된다.
32px 로 줄이면 접힘면 그라데이션은 뭉개지지만 **D 실루엣과 오렌지 블록은 남는다** — 그 상태에서도 구분되는 것을 채택 기준으로 삼았다.

## 7-3. 로고 자산

정본은 `frontend/src/components/Logo.tsx` 다. **파일이 아니라 인라인 SVG 로 둔다** —
`<img>` 로 불러오면 텍스트 색을 `currentColor` 로 화면 잉크에 맞출 수 없다. 자리는 `icons.tsx` 와 같은 규칙(자체 SVG 는 `components/` 안)이다.

| 항목 | 내용 |
|------|------|
| 원본 | `디인사이트 CI.ai` (PDF 1.6 호환). 저장소 밖에 있다 — 회사 자산이라 여기서 관리하지 않는다 |
| 채택 락업 | **D 마크 + 국문 텍스트 2줄**(#229) — 1줄 「디인사이트」(Pretendard Bold) · 2줄 「대영산전(주)-창원공장」(Medium, 1줄의 0.55배). 두 줄 묶음의 한글 위아래 끝이 D 의 위아래 끝과 같다 |
| 텍스트 경로 | Pretendard 윤곽선을 경로로 뽑아 둔다. `<text>` 는 웹폰트가 늦게 오면 대체 글꼴로 먼저 그려져 D 와 높이가 어긋난다. 「(주)」 괄호가 아래로 조금 내려가 `overflow="visible"` 이다 |
| 화면 | D 마크 + 텍스트 2줄 한 가지뿐이다. 로그인 · 사이드바. 읽는 이름은 「디인사이트 대영산전(주) 창원공장」 |
| 마크 상수 | `MARK` · `ORANGE` · `FOLD_STOPS` 가 **파비콘의 벡터 정본**이다 — `favicon-source.png` 를 이 상수로 렌더하고 작은 크기는 거기서 뽑는다(§7-2) |
| `className` | **필수다.** 기본값을 두면 호출부가 넘긴 값이 병합이 아니라 교체라, 크기 없는 className 하나에 `h-`/`w-` 가 사라지고 SVG 가 부모 폭 전체로 부푼다 (#154) |
| 텍스트 색 | `currentColor` — 놓인 자리의 글자색(`ink`)을 따른다 |
| D 마크 색 | 브랜드색 고정 |

**D 마크를 흰색 단색판으로 쓰지 않는다.** CI 에 화이트 단색판이 있지만 그건 색 재현을 보장 못 하는
인쇄·단색 용도다. 화면은 색을 정확히 낸다.

접힘면 그라데이션은 원본에서 **18x17 래스터 마스크**였다. 실측해 보니 y 방향 변화가 전혀 없는 완전한
수평 램프라 `linearGradient` 로 갈아끼웠다. 원본 PNG 와 픽셀 대조한 결과는 :

| 영역 | 최대 채널차 |
|------|-------------|
| 세로막대 · 오렌지 블록 등 평면부 | 2 (래스터화 잡음) |
| **접힘면 램프 안쪽** | **10** |

램프가 0 이 아닌 것은 5스톱 선형 근사가 원본의 미세한 비선형을 못 따라가기 때문이다.
눈으로는 구분되지 않지만 **"완전히 같다"고 적지 않는다.**

**파비콘도 같은 그라데이션을 써야 한다** — 좌표 주의는 §7-2 「재생성 절차」.

**경로 좌표를 손으로 고치지 않는다.** 벡터 원본에서 뽑은 값이며, 고칠 일이 생기면 원본에서 다시 뽑는다.

### 배치

| 자리 | 크기 |
|------|------|
| `LoginPage` 좌측 상단 | `h-8 md:h-10` |
| `Sidebar` 최상단 | `h-9` |

**모바일 헤더에는 로고를 두지 않는다(#235)** — 드로어를 열면 사이드바 로고가 나온다.

사이드바 로고는 `h-9` 다(#233) — 2줄째가 1줄의 0.55배로 고정이라, 2줄째 한글 몸통이 약 10px 로 읽힌다.

사이드바에서 폭이 좁아질 때 마크로 줄이는 분기는 **두지 않았다.** 락업은 `h-9` 에서 149px 이고
사이드바 최소 폭 200px 에서 로고 칸의 좌우 패딩(`px-6`, 24px씩)을 빼면 152px 라 늘 들어간다(여유 3px).
`h-10` 은 166px 라 최소 폭에서 넘친다.

## 8. 적용 결과

화면 코드에 남은 `zinc-*` 색은 0건이고, **화면이 쓰는 색은 아래 「색 리터럴이 허용되는 자리」 밖에서는 전부 토큰이다.**
그래서 팔레트를 바꿔도 화면의 색 클래스는 바뀌지 않는다.

### 색 리터럴이 허용되는 자리

토큰이 유일한 출처라는 말은 **아래 자리를 뺀 화면 코드**에 한정된다. **이 표가 허용 목록의 정본이다.**

| 자리 | 값 | 왜 토큰이 아닌가 |
|------|-----|-----------------|
| `frontend/src/index.css` | 토큰 16개 | 정본 |
| `frontend/src/components/Logo.tsx` | 브랜드색 2 + 램프 5스톱 | **로고는 화면 토큰을 따라가면 안 된다.** CI 색은 고정이어야 한다 — 토큰으로 빼는 순간 화면 색을 바꿀 때 로고가 다른 회사 색이 된다. 파비콘도 여기서 렌더하므로 사본을 따로 두지 않는다 |
| `frontend/index.html` | `theme-color` **1개** | `<meta>` 는 CSS 변수를 못 읽는다. `canvas` 와 **같은 값을 손으로 맞춘다**. `media="(prefers-color-scheme: …)"` 로 두지 않는다 — OS 가 다크면 주소창만 다크가 된다 |
| 사진·영상 위 오버레이 — `chat/ImageLightbox.tsx` · `chat/Composer.tsx` 썸네일 | `bg-black/*` · `bg-white/*` · `text-white*` · `border-white/*` | 아래 면이 **토큰이 아닌 이미지**라 화면 색과 무관하다 |
| 모달·드로어 뒤 스크림 — `ConfirmModal.tsx` · `pages/AdminUsersPage.tsx`(발급 모달) · `pages/ChatPage.tsx`(모바일 드로어) | `bg-black/40`(확대 보기는 위 사진 오버레이 줄 — `bg-black/90`) | 화면 전체를 가리는 반투명 막이라 바탕 토큰과 짝지을 대상이 없다 |
| 문서 그림 바탕 — `chat/DocFigure.tsx` | `bg-white` | 그림 자체가 화면 토큰과 무관한 이미지다 |

**[CONVENTIONS.md](../CONVENTIONS.md) 「스타일」은 이 표를 가리킨다.** 자리를 늘리면 이 표를 고친다.

**`index.css` 와 `Logo.tsx` 는 같은 값을 공유하지 않는다.** `accent`(`#08719B`)의 출처는 **홈페이지 `index.css` 의
`--brand-deep`** 이다 — 저장소 밖의 값과 짝이다. 홈페이지가 그 값을 바꾸면 이 앱은 따라가지 않으므로,
**색을 다시 맞출 때는 `dinsight-renew/src/index.css` 의 `--brand*` 와 `tailwind.config.js` 의 `dark` · `dark-light` · `surface` 를 함께 본다.**
게이트 셋(`check-doc-refs` · `check-doc-sections` · `check-doc-versions`)은 이 대응을 보지 않는다.

화면별 배치는 구현이 정본이며, 기능 단위 명세는 `docs/01_specs/features.md` 에 있다.
