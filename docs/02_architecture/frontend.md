# Frontend Architecture

React 19 + TypeScript + Vite 8 + Tailwind CSS 4. 반응형 웹(PC·모바일 브라우저) 단일 SPA.
전체 시스템 그림은 [overview](./overview.md), API 계약은 [api.md](../01_specs/api.md) 에 있다. 여기서는 프론트 내부 설계만 다룬다.

## 폴더 구조

| 경로 | 역할 |
|------|------|
| `frontend/src/pages/` | 라우트 단위 화면 — `LoginPage` · `ChatPage` · `MyPage` · `AdminPage` |
| `frontend/src/components/` | 재사용 컴포넌트. 기능이 커지면 `components/chat/` 처럼 하위 폴더 |
| `frontend/src/hooks/` | 도메인 훅 — `useChat.ts` 와, 그것이 쓰는 진행 단계 표시 큐 `useStageQueue.ts` |
| `frontend/src/lib/` | `api.ts`(fetch 래퍼·토큰) · `endpoints.ts`(엔드포인트 함수·SSE 파서) · `types.ts`(공유 타입) · `limits.ts`(서버 상한과 맞춘 입력 상한) · `docFigures.ts`(그림 표식 파서) |
| `frontend/src/auth/` | Context Provider |
| `frontend/src/test/` | Vitest 셋업 |

## 라우팅

`frontend/src/App.tsx` (React Router 8).

| 경로 | 화면 | 보호 |
|------|------|------|
| `/login` | `LoginPage` — 로그인 전용. 계정은 관리자가 발급한다 | 공개 |
| `/` | `ChatPage` | `ProtectedRoute` |
| `/me` | `MyPage` | `ProtectedRoute` |
| `/admin` | `AdminPage` — 문서 관리 · 사용자 관리 | `ProtectedRoute` + **관리자만** |
| 그 외 | `/` 로 리다이렉트 | 해당 없음 |

`frontend/src/components/ProtectedRoute.tsx` 는 세 갈래다 — `loading` 중이면 로딩 표시, 끝난 뒤 사용자가 없으면
`/login` 으로 리다이렉트, 있으면 자식을 렌더한다. 검증이 끝나기 전에 판정하지 않는 것이 요점이다.

## 상태관리

**외부 상태 라이브러리를 쓰지 않는다.** 서버 캐시 라이브러리(react-query 등)도 없다.
화면 사이를 건너다니는 상태가 **Context 하나**(`AuthContext`)뿐이고 나머지는 쓰는 쪽이
들고 있어서, 라이브러리 도입이 이득보다 크지 않다고 봤다. 아래 표의 셋 중 뒤의 둘은 Context 가 아니다 —
`useChat` 은 쓰는 훅이, 토큰은 모듈 변수가 보유한다.

| 상태 | 보유자 | 비고 |
|------|--------|------|
| 로그인 사용자 | `frontend/src/auth/AuthContext.tsx` | 기동 시 `/api/auth/me` 로 토큰 유효성 확인. **401 일 때만 토큰 폐기** — 네트워크 · 5xx 면 토큰을 두고 3초 간격으로 최대 10회 다시 묻는다(#250, 배포 · 재기동 중 새로고침) |
| 대화·메시지·스트리밍 | `frontend/src/hooks/useChat.ts` | 대화 목록, 활성 대화, 메시지 배열, 스트리밍 여부, 진행 단계, 오류를 한 훅이 보유(진행 단계 큐는 `useStageQueue` 에 위임) |
| 인증 토큰 | `frontend/src/lib/api.ts` 모듈 변수 + `localStorage` | React 상태가 아님 — 렌더링과 무관하게 요청 시점에 읽혀야 함 |

테마 상태는 없다 — 화면은 라이트 하나다([design-system.md](./design-system.md) §1).

## API 통신

- API 호출은 `frontend/src/lib/api.ts` 의 `api.get/post/patch/del/postForm` 을 통한다.
  **모든 인증 요청은 `authFetch` 를 거친다**(#390) — `api.*` 의 `request` · 채팅 스트림(`endpoints.ts` `streamChat`) · 문서 그림 로드
  (`docFigures.ts` `loadFigure`, blob 을 objectURL 로)가 같은 `authFetch` 를 지난다. **직접 `fetch` 하는 곳은 `ImageLightbox.download()` 하나**다 —
  서명 URL(`?token=`)이라 Bearer 가 필요 없고 blob 으로 받아야 해서다.
- 엔드포인트 함수는 `frontend/src/lib/endpoints.ts` 에 둔다. **대부분은 `api.*` 를 한 줄로 감싼 것**이고,
  래퍼로 안 되는 것만 함수로 편다 — 멀티파트 업로드 둘(`uploadFile` · `uploadDocument`)과 채팅 스트림이다.
  **`AuthContext` 는 예외로 `/api/auth/me` 와 `/api/auth/login` 을 직접 부른다** — 세션 수명을 그 안에서
  닫아 두려는 것이고, 그래서 `endpoints.ts` 에 인증 함수가 없다.
- **응답이 도착한** 실패는 `ApiError(status, message)` 로 통일하고, 서버가 `message` 를 주면 그대로 보여준다 — 없으면 `요청 실패 (n)` 로 떨어진다. 네트워크 단계 실패(CORS 거절·오프라인·중단)는 `fetch` 또는 본문 읽기가 reject 되어 이 경로를 타지 않는다.
- 비밀번호 변경 응답의 **새 토큰으로 반드시 교체**해야 한다. 서버가 변경 시각 이전 토큰을 전부 무효화하므로,
  교체하지 않으면 "변경했습니다"를 띄운 직후부터 모든 요청이 401 이 된다.
- **401 이면 어떤 요청에서든 세션을 비우고 로그인으로 돌아간다**(`setUnauthorizedHandler`). 단 로그인·비밀번호 변경의 401 은
  "자격 증명이 틀렸다"는 뜻이라 세션을 유지한다(`CREDENTIAL_PATHS`) — 그러지 않으면 비밀번호 오타 한 번에 로그아웃된다.
- **응답 헤더 `X-Refresh-Token` 이 오면 토큰을 교체한다**(FEAT-OPS-003). 만료가 임박했을 때만 온다.
  교체는 **`authFetch` 한 곳**에서 일어난다 — `adoptRefreshedToken` 을 부르는 곳이 그곳뿐이다. `request` · 채팅 스트림 · 그림 로드가 모두 `authFetch` 를 지나므로
  새 인증 요청도 `authFetch` 를 거쳐야 한다. 우회하면 그 경로만 쓰는 사용자(예: **채팅만 쓰는 사용자**)는 갱신을 못 받고 두 시간마다 튕긴다.
  헤더가 없으면 기존 토큰을 그대로 둔다 — 서버가 CORS 노출 헤더 등록을 빠뜨리면 `null` 이 오는데,
  그때 토큰을 지우면 멀쩡한 세션이 날아간다.
  **요청을 보낸 세션과 지금 세션이 다르면 헤더를 버린다(#363)** — `authFetch` 가 송신 시점 토큰을 넘긴다. 로그아웃 → 다른 계정 로그인 사이에
  늦게 돌아온 응답이 이전 계정의 새 토큰으로 지금 세션을 덮기 때문이다.
- **다른 탭이 토큰을 지우거나 바꾸면 따라간다(#412)** — `api.ts` 가 `storage` 이벤트(다른 탭의 변경에만 온다)를 듣는다. 같은 계정의 재발급이면
  모듈 토큰만 맞추고, 지워지거나 다른 계정 · `clear()` 면 **저장소를 건드리지 않고 페이지를 다시 읽는다** — 토큰만 바꾸면 화면과 요청의 계정이 갈리고,
  로그아웃 처리를 부르면 늦게 처리된 삭제가 다른 탭의 새 로그인을 지운다. 안 따르면 로그아웃한 탭의 모듈 토큰이 살아 있어 재발급 때 localStorage 에 다시 써 넣는다(공용 PC).

### 채팅 스트림 수신

`EventSource` 가 아니라 **fetch + ReadableStream** 이다 — `EventSource` 는 `Authorization` 헤더를 실을 수 없다.
`streamChat` 이 `\n\n` 경계로 SSE 프레임을 잘라 `meta → stage* → token* → citations → done` 을 콜백으로 흘린다.

첨부 이미지는 `<img src>` 가 헤더를 못 실으므로 **쿼리 서명 토큰이 붙은 URL**을 쓴다. 이 URL 은 재조회 시점에
서버가 새로 서명하므로 저장해 두고 재사용하지 않는다.

## 스트리밍 UI 규칙

`useChat` 이 지키는 계약이며, 어기면 화면과 재조회 결과가 어긋난다.

- **토큰은 진행 중인 답변 하나만 새 객체로 바꾼다 — 그 동일성이 재렌더를 막는다**(#405). `MessageBubble` · `Sidebar` 는
  `memo` 이고, `ChatPage` 가 사이드바에 넘기는 핸들러는 `useCallback` 으로 고정한다. 지난 메시지를 새 객체로 만들거나
  인라인 함수를 넘기면 토큰마다 지난 답변의 마크다운 파싱과 대화 목록 렌더가 되살아난다(`MessageListRender` · `ChatPageRender` 테스트가 잡는다).
- **진행 단계는 최소 표시 시간(350ms)만큼 붙잡는다.** 목업은 단계가 같은 순간에 도착해 표시 시간이 0이 된다.
  없는 단계를 만들거나 순서를 바꾸지는 않는다 — 실제 도달한 단계에만 시간을 준다.
- **단계를 보여주는 동안에는 답변 버블을 내지 않는다.** 단계가 끝나면 그 자리가 답변 텍스트로 교체된다.
- **대화를 떠나면 돌던 스트림을 끊는다.** 안 끊으면 이전 대화의 단계 줄이 새 화면에 잔류한다.
- **`await` 뒤의 상태 반영은 대화 세대가 그대로일 때만 한다**(#93). 대화를 바꾸는 모든 진입점이
  세대 번호를 올리고, 느리게 도착한 응답은 세대가 다르면 버린다. 없으면 **남의 대화 이력 위에
  새 턴이 얹히고**(생성 왕복 중 전환) **사이드바와 본문이 갈린다**(선택 응답 역순 도착).
  어느 쪽이든 새로고침하면 그 턴이 사라져 사용자는 무엇이 저장됐는지 알 수 없다.
- **대화를 고르면 이력이 올 때까지 본문에 로딩 표시를 둔다**(#291, 모바일 · 데스크탑 같은 자리). 없던 동안에는
  직전 대화 내용이 남거나 빈 화면 안내가 떠, 느린 망에서 「눌렀는데 반응이 없다」로 보였다. `loadingMessages` 도
  위 세대 규칙을 따른다 — A→B 를 빠르게 누르면 A 가 먼저 와도 B 가 올 때까지 켜져 있고, 실패해도 꺼진다.
- **새 대화 생성 왕복 중에는 전송을 막는다.** `streaming` 은 스트림이 열려야 참이 되므로 그 구간을
  덮지 못한다. 막지 않으면 대화가 둘 만들어지고, 두 번째 컨트롤러가 `abortRef` 를 덮어쓴 뒤 첫 번째의
  `finally` 가 그것을 지워 **정지 버튼이 무력화된다**.
- **이력 로딩 중에도 전송을 막는다**(#323). 받아 들이면 말풍선이 직전 대화의 목록에 붙고, 곧 도착한 이력이
  목록을 갈아 끼워 **답 말풍선이 사라진다** — `send` 는 세대를 올리지 않으므로 그 이력은 버려지지 않는다.
- **`send` 는 받아들였는지를 돌려주고, 입력창은 받아들였을 때만 비운다**(#323). 조용히 버리면 입력이
  사라지고 이미 올린 첨부는 회수 크론을 기다리는 고아가 된다. 기존 대화는 곧바로, 새 대화는 **생성 왕복이 끝난 뒤에**
  정해진다(#349) — 생성이 실패하면 보낸 것이 없으므로 오류 배너만 뜨고 입력 · 첨부가 남는다. 스트림 완료는 기다리지 않는다.
  입력창은 `busy`(`loadingMessages || creating`) 동안 보내기 버튼을 끄고 Enter 도 받지 않으며, 버튼에 그 이유를 적는다(#101).
  그사이 이어 쓴 글 · 더한 첨부는 받아들여진 뒤에도 남는다 — 보낸 것만 걷는다. 보낸 카드는 그동안 지워도 서버 첨부를 지우지 않는다.
- **중단은 오류가 아니다.** 받은 데까지 `complete` + `stopped` 로 두고, 받은 것이 없으면 빈 버블을 남기지 않는다
  (서버도 부분 텍스트가 비면 저장하지 않으므로, 남기면 새로고침에 사라져 어긋난다).
  서버 저장분은 화면보다 토큰 하나 많을 수 있다 — 끊긴 직후의 첫 전송은 성공으로 끝나기도 한다(#487 실측, 스트리밍 중에 끊으면 FIN 5/5 · RST 0/5).
  **200 을 받기 전에** 끊기면 질문 말풍선도 걷는다(#435) — 서버는 질문을 저장한 뒤에 200 을 돌려주므로(`onOpen`), 그 전에 끊긴 요청은
  서버에 닿지 않았을 수 있다. 200 뒤의 중단은 질문을 남긴다.
  **200 이 없었다고 서버에 없는 것은 아니다** — 서버는 질문 저장 · 첨부 연결을 커밋한 뒤 200 을 돌려주므로 그 사이에 끊으면 저장돼 있다.
  그래서 끊은 뒤 서버에 물어 가른다(#440, 확인이 끝날 때까지 다시 보내기는 거절). 그 턴이 만든 **새 대화는 「비었을 때만 지우기」**
  (`DELETE …?ifEmpty=true`, #447)로 묻는다 — 204 면 저장 전이었고 대화도 지워졌다, 409 면 저장된 것이다. 서버가 한 잠금 안에서
  가르므로 확인과 삭제 사이에 저장이 끼지 않는다. **기존 대화는 이력을 물어** 마지막 메시지가 보낸 질문인지 본다 :
  - 저장됨(409 · 마지막 메시지가 보낸 질문) → 이력을 그대로 보인다. 되돌리지도 지우지도 않는다. 답은 오지 않는다(아래 「남은 한계」)
  - 없으면 → **보낸 글과 첨부 카드를 입력창에 되돌린다**(`send` 의 `giveBack`). 그사이 쓴 글은 뒤에 잇고, 카드는 파일에서 미리보기를
    다시 만든다(서버 첨부는 그대로). 그사이 더한 카드와 합쳐 5장을 넘으면 뒤에 더한 것을 걷고 상한 안내를 띄운다.
    새 대화는 이미 지워졌으므로 새 대화 상태로 돌아간다 — 목록은 지운 뒤에 다시 받는다
  - 확인 · 조건부 삭제가 실패하면 → 글은 되돌리고 대화는 남는다. 409 인데 이력만 못 받았으면 되돌리지 않고 걷었던 질문 말풍선을 되살린다.
    조건부 삭제가 404 면 이미 지워진 것으로 보고 지운 것과 같게 처리한다
  - 대화를 옮겨 끊긴 경우는 되돌리지 않는다(입력창이 대화마다 따로가 아니다). 입력창이 언마운트된 뒤의 되돌리기는 무시한다
  - 남은 한계(리뷰에서 확인, 빈도 낮음 — 기존 대화 쪽은 전송 식별자가 있어야 막힌다, #447 에서 범위 밖으로 결정) :
    - 기존 대화에서 확인이 서버의 질문 저장보다 먼저 처리되면 「없음」으로 판정한다 — 질문이 뒤늦게 저장되고, 되돌린 카드는 이미 쓰여
      다시 보내면 400 「이미 보낸 첨부」다. 새 대화는 조건부 삭제(#447)로 이 경합이 없다
    - 기존 대화의 마지막 메시지가 같은 글(답이 아직 저장되지 않은 직전 턴)이면 「저장됨」으로 잘못 보고 글을 되돌리지 않는다
    - 저장됨으로 판정한 턴에는 답이 없다(#487 실측) — 서버는 끊김을 끊긴 뒤 첫째 · 둘째 전송에서 알아채 생성을 멈추고,
      보낸 토큰이 없으니 답 행을 남기지 않는다. 질문만 답 없이 이력에 남고(다음 턴의 이력에도 들어간다) 글 · 첨부는 입력창에 돌아오지 않아,
      다시 물으려면 새로 쳐야 한다
    - 저장됨으로 판정한 뒤 곧바로 다시 물으면, 서버가 끊김을 아직 알아채지 못했을 때만 429(사용자당 동시 스트림 1) — 알아채는 것은
      다음 이벤트(단계 · 토큰)를 쓸 때라 모델이 그것을 늦게 낼수록 길다. 실측(#487)에서 끊은 뒤 50ms 재전송은 10회 중 1회 429(다음 전송이 1.5초 뒤), 나머지는 200
    - 로그아웃으로 끊기면 토큰이 먼저 지워져 빈 대화 삭제가 401 로 실패한다
- **중단 버튼이 나타난 뒤 500ms 안의 클릭은 무시한다**(#435). 보내기와 같은 자리라, 빠른 두 번 탭(약 300ms)의 두 번째가
  중단으로 떨어져 첫 토큰 전에 질문이 끊겼다.
- **`onDone` 이 확정한 메시지는 이후 경로에서 건드리지 않는다.** 서버가 정상 저장한 답변에 `stopped` 를 세우면
  화면(배너 없음)과 재조회(배너 있음)가 갈린다.
- **무자료 배너는 텍스트 접두가 아니라 "출처 0건"에서 파생한다.** 스트리밍 중과 중단된 답변에는 붙이지 않는다.
- **종단 이벤트 없이 끝난 스트림은 오류로 귀결시킨다**(#85). `api.md` 의 이벤트 순서는 `done`·`error`
  둘로 끝나지만 **셋째 경로가 있다** — 서버 SSE 타임아웃은 emitter 를 닫을 뿐 어느 쪽도 싣지 못하고
  (닫힌 뒤의 `send` 는 예외다), 프록시 idle timeout · 네트워크 절단도 같은 모양으로 도착한다.
  그때 `reader.read()` 는 예외 없이 `done:true` 를 주므로, 종단 이벤트를 받았는지 따로 들고 있지 않으면
  `streamChat` 이 **정상 반환**해 호출부의 `catch` 도 `onDone` 도 돌지 않는다 — 말풍선이 `streaming` 인
  채 영구히 남고 오류 배너도 정지 버튼도 없다. 토큰이 일부 온 뒤 끊기면 **잘린 답변이 정상 완료된
  답변과 같은 모양**으로 보인다.
  **서버를 고쳐도 이 방어는 필요하다** — 종료 이벤트를 약속할 수 있는 것은 애플리케이션 계층뿐이고,
  이 프로젝트는 Cloudflare Tunnel 뒤로 배포되어 프록시가 한 겹 더 낀다.

## 문서 그림 표식 렌더

답변 본문의 `[[그림:<key>]]` 을 그림으로 바꾼다(FEAT-CHAT-004). 파서는 `frontend/src/lib/docFigures.ts`,
그리는 쪽은 `frontend/src/components/chat/DocFigure.tsx` 다.

표식의 동작(덜 도착한 표식 숨김 · 404 면 자리를 비움 · 출처 스니펫은 `[그림]` · 누르면 확대 보기)은 `features.md` FEAT-CHAT-004 가 정본이다.

- **답변 본문은 마크다운으로 그린다(#270).** 표식으로 먼저 자르고, 표식 사이의 글만 `components/chat/Markdown.tsx`(react-markdown + remark-gfm)로 그린다.
  **원시 HTML 은 그리지 않는다**(react-markdown 기본, rehype-raw 없음) · 위험한 링크 스킴은 기본 urlTransform 이 지운다 ·
  **마크다운 이미지(`![](url)`)도 그리지 않는다**(#359, 바깥 주소를 곧바로 불러 값이 새는 길) — 자리에는 **alt 문구만** 글자로 남긴다(#365, 이미지를 감싼 링크가 빈 링크로 남지 않게) ·
  **마크다운 링크(`[글](url)`)도 누를 수 없는 글자로 그린다**(#414, 모델 출력에 실린 바깥 주소로 한 번 클릭에 대화가 새는 길) — 글자 뒤에 ` (호스트)` 를 밝히고, 호스트를 못 읽는 값(상대 경로 · http(s) 아님)은 글자만 ·
  표는 가로 스크롤 상자 안. **사용자 메시지와 출처 스니펫은 평문 그대로**다.
- **`Markdown` 은 `React.lazy` 로 지연 로딩한다(#417).** react-markdown · remark 묶음이 따로 청크(gzip 약 54KB)로 빠져 로그인 화면의 첫 JS 는 gzip 147.38KB → 92.76KB 였다(#417 시점 실측, 이후 달라질 수 있음). 청크가 오기 전 답변 자리는 `<Suspense>` fallback 으로 같은 글을 평문(`whitespace-pre-wrap`)으로 보인다. **청크를 못 받으면(재배포로 옛 청크가 사라짐 · 망 끊김) 평문으로 물러선다** — 그대로 두면 lazy 의 오류가 최상위 ErrorBoundary 까지 가 앱 전체가 오류 화면이 된다. `ChatPage` 가 로그인 뒤 청크를 미리 받아 둔다.
- **한국어 조사 앞의 굵게도 닫는다(#287).** 표준 강조 규칙은 닫는 `**` 앞이 문장부호 · 뒤가 글자면 굵게로 보지 않으므로
  `remark-cjk-friendly` 를 remark-gfm 뒤에 붙여 CJK 글자 옆에서만 이 규칙을 푼다.
- **그림은 Bearer 로 받아 objectURL 로 그리고, 키별로 한 번만 받는다.** objectURL 과 404(`null`)를 모듈 캐시에 두고 회수하지 않는다 —
  같은 그림이 여러 곳 · 재조회에서 다시 쓰이고, 개수는 원본 그림 수로 유계다. 네트워크 실패만 캐시하지 않아 다음 렌더가 다시 묻는다.

## 첨부 UI 계약

입력창(`frontend/src/components/chat/Composer.tsx`)과 말풍선(`frontend/src/components/chat/MessageList.tsx`)이
지키는 규칙이며, 어기면 파일이 서버에 남거나 탭 메모리가 샌다. 즉시 업로드 · 카드 삭제 시 서버 삭제 · 미리보기 URL 회수 ·
파일명 미표시(미리보기를 못 그리는 카드 포함, #317) · 비이미지 거절 · 확대 보기의 동작은 `features.md` FEAT-CHAT-001~003 이 정본이다.
여기는 프론트 구현 규칙만 둔다.

- **올라가지 않은 첨부가 있으면 보내기를 막는다.** 업로드 중·실패 카드가 하나라도 있으면 전송 버튼이 비활성이다.
  막지 않으면 그 이미지가 빠진 채 나가는데 화면에는 카드가 남아 있어 사용자는 갔다고 읽는다.
- **자동 스크롤은 사용자가 위로 올렸는지를 본다**(#100). 답변이 흐르는 동안 따라 내려가되,
  위로 올렸으면 멈추고 바닥으로 돌아오면 다시 붙는다. **「바닥에서 멀면 뗀다」로 두면 안 된다** —
  `scrollIntoView({behavior:'smooth'})` 의 애니메이션 중간 위치가 그 조건에 걸려 스스로 멈춘다.
  프로그램이 만든 스크롤은 늘 아래로 향하므로 **방향**을 봐야 걸러진다.
  **내가 보낸 질문은 위치와 무관하게 바닥으로 간다** — 판정은 배열의 끝이 아니라 「마지막 사용자
  메시지」로 한다. 전송 시 질문과 답변 버블이 함께 추가돼 끝은 늘 assistant 다.
- **`title` 속성에만 기대지 않는다**(#101). 터치 기기는 툴팁을 띄우지 않으므로 그 안의 정보는
  모바일에서 존재하지 않는 것과 같다. 실패 사유는 **텍스트로** 내보내고, 비활성 버튼은 **왜
  비활성인지**를 함께 말한다 — 이유 없는 회색 버튼은 고장으로 읽힌다.
- **비동기 실패는 반드시 화면에 드러낸다**(#77·#78). 프라미스를 버리면 실패가 조용히 사라져
  「눌렀는데 아무 일도 안 일어난다」가 된다 — 삭제·이름 변경이 그랬다. **낙관적으로 먼저 적용한
  것은 실패 시 되돌린다** — 되돌리지 않으면 화면과 서버가 갈린 채 어느 쪽이 진짜인지 알 수 없다.
- **비동기 자원은 「떠났는지」를 표시로 들고 정리한다**(#75). 정리 함수가 `.then` 보다 먼저 돌면
  변수에 아직 아무것도 담겨 있지 않아 **정리할 대상을 못 본다.** `cancelled` 를 보고 뒤늦게 온 자원은 그 자리에서 해제한다.
  `auth/AuthContext.tsx` 의 `/api/auth/me` 재시도가 이 표시를 본다 — 떠난 뒤 도착한 응답은 버리고 재시도 타이머를 지운다.
- **언마운트에서 in-flight 요청을 끊는다**(#94). 스트림과 업로드 둘 다다 — 안 끊으면 로그아웃해도
  SSE 가 살아 **로그인 화면에 도달한 뒤에도 이전 사용자의 요청이 진행 중**이고, 업로드는 파일이
  서버에 남아 어떤 메시지에도 연결되지 않은 고아가 된다. **abort 보다 먼저 서버가 받아 버린 업로드**는
  뒤늦게 성공하므로, 언마운트가 `draftsRef` 를 비워 기존 회수 경로(`startUpload` 의 미등록 판정)가
  그대로 돌게 한다 — 비우지 않으면 회수 대신 언마운트된 컴포넌트에 `setDrafts` 를 시도한다.
- **미리보기 URL 회수는 눈으로 확인되지 않아 테스트가 유일한 게이트다**(`Composer.test.tsx` 가 회수 호출을 단언한다).
- **`+` 는 메뉴 없이 기기 선택창을 바로 연다(#289).** `accept` 는 **`image/*`** 다 — 서버 허용 목록으로 좁히면 Android 가
  카메라 없이 보관함으로 바로 들어가 촬영 길이 사라진다. 허용 밖 형식(HEIC 등)은 서버가 거절하고 카드에 오류로 남는다.
- **확대 보기는 전송 전·후가 같은 컴포넌트다**(`ImageLightbox.tsx`) — `src` 가 로컬 objectURL 이냐 서명 URL 이냐만 다르다.
  핀치 줌을 받으려면 이미지에 `touch-action: none` 을 준다 — 없으면 브라우저 기본 제스처가 먼저 먹어 핀치 이벤트가 오지 않는다.
- **드래그 오버레이는 진입/이탈을 센다.** `dragleave` 만 보고 걷으면 자식 요소를 지날 때마다 깜빡인다.

### 화면 골격

- 화면 높이는 `100dvh` 다. `h-screen` 은 iOS 주소창이 접힐 때 입력창을 화면 밖으로 밀어낸다.
  **`dvh` 는 가상 키보드에 반응하지 않는다(#221).** 키보드가 열리면 보이는 영역(`visualViewport`)만 줄고 입력 쪽으로
  이동해 헤더가 화면 밖으로 밀려 나갔다. 그래서 채팅 화면은 ① 떠 있는 동안 `html` 의 스크롤과 튕김(`overscroll-behavior`)을
  끄고 ② `visualViewport` 가 바뀔 때마다 루트 높이를 그 높이로 맞추고 문서 스크롤을 0 으로 되돌린다(`ChatPage.tsx`).
  Android Chrome 은 `index.html` viewport 의 `interactive-widget=resizes-content` 로 레이아웃 자체가 줄어든다.
  **이 메타는 전 페이지에 걸린다** — Chrome 108 전의 기본 동작과 같다. 로그인·관리·마이 페이지는 `min-h-[100dvh]` +
  문서 스크롤이라 키보드가 열리면 최소 높이만 줄고 내용은 그대로 스크롤된다.
  `scrollTo(0, 0)` 은 데스크톱 창 크기 변경에도 불리지만 채팅 화면은 문서가 스크롤되지 않아(목록만 스크롤) 잃는 위치가 없다.
  **헤드리스 브라우저는 가상 키보드와 iOS 튕김 · 확대를 재현하지 못한다** — 이 부분은 #221 의 실기기 확인이 정본이다.
- **입력 글자는 모바일 16px · md 이상 15px 이다(#221 후속).** iOS Safari 는 16px 미만 입력에 포커스하면 화면을 확대하고
  포커스가 풀려도 되돌리지 않는다 — 실기기에서 입력 칸이 위로 솟고(확대된 보이는 영역 높이가 루트에 들어감) 포커스를
  풀면 가로 스크롤이 생겼다. 새 입력을 만들 때도 `text-base md:text-[15px]` 를 지킨다(`TextInput` 은 이미 그렇다).
  같은 이유로 `visualViewport.scale` 이 1 이 아닐 때(사용자가 손가락으로 확대한 동안)는 높이 맞춤을 하지 않는다.
- 모바일 헤더는 메뉴 버튼 · 대화 제목 · 새 채팅 버튼뿐이다. 로고는 드로어 안 사이드바에만 있다(#235, `design-system.md` 7-3).

## 배포 (Vercel)

**운영 중** : https://rag-chatbot-jade-pi.vercel.app (Vercel 프로젝트명 `rag-chatbot`)

preview 배포의 출처는 백엔드 `ALLOWED_ORIGINS` 에 없어 CORS 로 막힌다.

`frontend/vercel.json` 이 빌드 명령·출력 디렉터리와 **SPA 리라이트**를 고정한다. 리라이트가 없으면
`/me` 를 직접 열거나 새로고침할 때 404 가 난다 — 라우팅을 `BrowserRouter` 가 하기 때문이다.

같은 파일이 **보안 헤더**를 모든 경로에 붙인다(#404). 없으면 Vercel 기본 HSTS 하나뿐이라 다른 사이트가 `/admin` 을
투명 iframe 으로 덮어 「삭제 → 확인」 클릭을 유도할 수 있었다(클릭재킹).

| 헤더 | 값 | 이유 |
|------|-----|------|
| `X-Frame-Options` | `DENY` | 프레임 삽입 거부(클릭재킹) |
| `X-Content-Type-Options` | `nosniff` | 형식 추측 금지 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 다른 출처에는 경로 없이 출처만 |
| `Content-Security-Policy` | 스크립트 `'self'` · 연결 `'self'` + 백엔드 · 이미지 `'self'` + 백엔드 + `blob:` + `data:` · `frame-ancestors 'none'` | **강제한다**(#411). Report-Only(#404)로 운영 화면 전부(대화 목록 · 스트리밍 · 첨부 업로드/미리보기/확대 · 문서 그림 · 마이페이지 · 관리자)를 돌아 위반 0 을 본 뒤 바꿨다. 정책을 넓힐 때는 Report-Only 로 먼저 올린다 |

**CSP 에 백엔드 주소(`https://api.chseong.fyi`)가 박혀 있다.** `VITE_API_BASE_URL` 을 바꾸면 이 값도 함께 바꿔야 한다 —
강제로 바꾼 뒤에 어긋나면 모든 API 호출 · 첨부 이미지가 막힌다.

GitHub 저장소가 연결돼 `main` 푸시가 자동 배포된다. **다시 연결할 때 : Root Directory = `frontend`** — 모노레포라 빼면 루트에서 빌드해 실패한다.

배포 전 반드시 할 것 :

1. Vercel 프로젝트 환경변수에 `VITE_API_BASE_URL` = 백엔드 공개 주소를 넣는다(빠뜨렸을 때의 증상은 `frontend/.env.example`).
   Vite 는 이 값을 **빌드 시점에 치환**하므로, 값을 바꾸면 재배포해야 한다.
2. 백엔드의 `ALLOWED_ORIGINS` 에 Vercel 도메인을 넣는다(백엔드 설정 — `backend.md` 「배포」).
   안 넣으면 브라우저가 모든 호출을 CORS 로 막는다.

백엔드를 로컬에 두고 터널로 노출하는 데모 구성이면 `VITE_API_BASE_URL` 이 터널 주소가 된다(바뀌면 1번대로 재배포).
절차와 터널 도구 선택은 [backend.md](./backend.md) 「배포」 참고.
