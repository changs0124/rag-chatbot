## 절차 메모

- **2026-07-27부터 PR 흐름을 적용함** : 작업 브랜치 → PR → CI 3잡 초록 → 머지. 그 이전 구간은 `main` 직접 push였고, CI는 push 트리거로 매 커밋 검사됨(게이트 6 "Phase별 PR이 단독 CI 통과"의 취지는 커밋별 초록으로 충족했으나 **PR 단위 검사는 아니었음**)
- 이미 `main`에 올라간 커밋을 PR로 되돌리려면 히스토리 재작성 + 강제 push가 필요해 하지 않음. 되돌림 비용이 기록 정확성보다 큼
- CI가 검사하는 3잡 : `backend (test + build)` · `frontend (lint + test + build)` · `docs (참조 실재 검사)`
