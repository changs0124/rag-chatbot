## 절차 메모

- **2026-07-27부터 PR 흐름을 적용함** : 작업 브랜치 → PR → CI 3잡 초록 → 머지. 그 이전 구간은 `main` 직접 push였고, CI는 push 트리거로 매 커밋 검사됨(게이트 6 "Phase별 PR이 단독 CI 통과"의 취지는 커밋별 초록으로 충족했으나 **PR 단위 검사는 아니었음**)
- 이미 `main`에 올라간 커밋을 PR로 되돌리려면 히스토리 재작성 + 강제 push가 필요해 하지 않음. 되돌림 비용이 기록 정확성보다 큼
- **기입 규칙** : 자기 행에 자기 머지 결과를 적으려면 PR이 끝없이 이어지므로, **run 번호는 뒤이은 PR이 있을 때만 채우고** 없으면 "PR 체크 3잡 pass(머지 전 확인)"로 적음. 머지 커밋 해시는 git 히스토리가 원장임
- **CI가 검사하는 잡(2026-07-28~ 6잡)** : `backend (test + build + 케이스 수 하한)` · `frontend (lint + test + build + 케이스 수 하한)` · `docs (참조 실재 + 계획서 필수 표)` · `secrets (시크릿 스캔)` · `deps (백엔드 의존성 취약점)` · `deps (프론트 의존성 취약점)`
  o 2026-07-27까지는 3잡이었음(`backend (test + build)` · `frontend (lint + test + build)` · `docs (참조 실재 검사)`). **위 표 1~5행의 "3잡"은 당시 사실이므로 그대로 둠**
