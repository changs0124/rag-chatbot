## [2026-08-19]

### Added
- **개발 문서 10종 정비 (`/project-docs-gen` 체계)** — 코드가 먼저 있고 문서가 없던 상태를 뒤집음. `docs/99_inbox/` 에 `01-requirements` ~ `10-scenarios` 를 두고 `REQ-` · `FEAT-` · `SCR-` · `API-` · `FLOW-` · `TC-` ID 체계를 세움
  - 기존 첨부 미리보기 3종은 **정본 파일명으로 옮겨 누적 병합**(`features.md` → `05-features.md` 등). 새 기능마다 파일을 늘리지 않고 한 문서에 쌓음
  - 템플릿 기본값이 이 저장소와 어긋나는 부분은 **골격만 따르고 값은 실제로 바꿈** — MySQL(`BIGINT AUTO_INCREMENT` · `DATETIME`) → PostgreSQL uuid · `timestamptz`, 응답 `{success,data}` → `{code,message}`, `/api/v1` → `/api`, 권한 없음 403 → 404 은닉. 그대로 옮기면 문서가 코드와 어긋남
  - 실제 스키마와 대조해 `06-erd.md` 2건을 고침 — 인덱스명을 비워뒀던 것(`idx_citations_message` 는 `(message_id, seq)` 복합)과 V1 의 `set_updated_at()` 트리거 누락
  - `docs/01_specs/live-integration.md` 신설 — 키·Vector Store 확보 후 투입 절차와 **실물로 확인된 적 없는 가정 5건**(이벤트명 · annotation 스키마)을 증상과 함께 나열함
- **턴별 토큰 사용량 기록 (FEAT-OPS-001)** — 앱 안에서 비용을 볼 수단이 전혀 없었음. 완료 이벤트의 `usage` 를 이미 받고 있으면서 인용만 뽑고 버리던 것을 주움(추가 API 비용 0)
  - `messages.input_tokens` · `output_tokens` 신설(V4). **nullable** — `0` 을 기본값으로 두면 "모르는 것"과 "정말 0"이 합계에서 섞임. 사용자 메시지 · 목업 · 중단된 턴 · V4 이전 행이 모두 "모르는 것"임
  - 조회는 `where input_tokens is not null` 로 거름. 빼면 턴당 평균이 실제보다 낮게 나옴(SQL 예시는 `docs/99_inbox/06-erd.md` 6절)
  - Jackson 의 `asInt()` 는 없는 노드에 0 을 주므로 쓰지 않음 — 그대로 쓰면 "usage 가 안 왔다"와 "정말 0 토큰"이 저장에서 구분되지 않음
  - 화면은 만들지 않음. 무엇을 볼지는 데이터가 쌓인 뒤에 정함
- **예외 최종 폴백 + 요청 상관 ID (FEAT-OPS-002)** — `GlobalExceptionHandler` 에 `Exception` 핸들러가 없어, 예상 못 한 예외만 Spring 기본 형태(`timestamp`·`status`·`error`·`path`)로 나가 **이 경로에서만 응답 계약이 깨졌음**. 프론트는 `message` 를 못 찾아 "요청 실패 (500)" 만 띄웠고 서버 로그에도 어느 요청이었는지 상관 지을 기록이 없었음
  - 응답은 `{"code":"INTERNAL_ERROR","message":"처리 중 오류가 발생했습니다 (오류 번호: a1b2c3d4)"}`. **예외 메시지를 싣지 않음** — SQL 조각·클래스 이름이 그대로 나가면 정보 노출임
  - 도메인 예외(400·404·409·429)는 폴백에 걸리지 않음을 케이스로 잠금 — 폴백이 앞 핸들러를 가로채면 전부 500이 됨
  - SSE 스트림 도중 오류는 대상이 아님. 응답이 이미 시작돼 상태 코드를 바꿀 수 없고 `ChatService` 가 `event: error` 로 따로 처리함
- **세션 슬라이딩 재발급 (FEAT-OPS-003 · REQ-AUTH-005)** — 120분 고정 만료에 갱신 수단이 없어 업무 도중 세션이 끊기면 작성하던 내용이 날아갔음. 남은 수명이 임계(`JWT_REFRESH_THRESHOLD_MINUTES`, 기본 30분) 미만이면 응답 헤더 `X-Refresh-Token` 으로 새 토큰을 보냄
  - 리프레시 토큰을 두지 않음 — 테이블·회전·재사용 탐지가 붙어 작업량이 3~4배인데, 기존 `password_changed_at` 무효화 규칙과 그대로 호환되는 슬라이딩으로 같은 목적을 달성함
  - **CORS 노출 헤더 등록을 케이스로 잠금** — 빠뜨리면 서버는 정상 발급하는데 브라우저가 값을 숨겨 **조용히 아무 일도 안 일어남**. 실패가 눈에 안 띄는 부류라 다른 검사로는 드러나지 않음
  - 프론트는 **두 경로 모두**에서 교체함 — `frontend/src/lib/api.ts` 래퍼와 `frontend/src/lib/endpoints.ts` 의 채팅 스트림. 스트림은 래퍼를 안 거치므로 한쪽만 하면 채팅만 쓰는 사용자는 갱신을 못 받음
  - 임계 `0` 이면 기능이 꺼져 종전 고정 만료로 돌아감(되돌리기 경로도 케이스로 검증)
- **관리자 권한 (FEAT-ADMIN-001 · REQ-ADMIN-004)** — `users.role` 신설(V5). 지금까지 로그인한 전원이 동등해 RAG 문서를 관리할 사람을 구분할 수단이 없었고, 그 때문에 문서 등록 경로 자체를 제품 안에 둘 수 없었음
  - 승격은 환경변수 `ADMIN_EMAILS` 명단으로만. **앱에 권한 상승 API 를 두지 않아** 공격면이 늘지 않고 통제권이 배포 설정에 남음. "첫 가입자 자동 승격"은 DB 초기화 시점에 외부인이 먼저 가입하면 그가 관리자가 되어 기각함
  - **강등을 함께 함** — 승격만 하면 명단에서 지운 계정이 영구히 관리자로 남아 명단이 통제 수단이 되지 못함. 명단을 통째로 비우면 전원 강등이며 그것이 맞는 동작임
  - 역할을 **JWT 클레임에 담지 않음** — 담으면 강등이 토큰 만료까지 반영되지 않음. 인증 필터가 이미 요청마다 사용자 행을 읽으므로 추가 쿼리가 없음
  - 명단에 있으나 미가입인 이메일은 **가입 시점에** 반영함. 기동 동기화는 이미 가입한 계정만 손대므로, 이 경로가 없으면 명단에 미리 넣어 둔 사람이 가입해도 재기동 전까지 일반 사용자임
  - `GET /api/auth/me` 응답에 `role` 추가 — 프론트가 관리 메뉴 노출을 판단할 값. **표시 판단일 뿐 접근 제어가 아님**
- **RAG 문서 관리 (FEAT-ADMIN-002 · REQ-ADMIN-001·002·003)** — 공용 Vector Store 에 문서를 넣는 경로가 제품 안에 없어 OpenAI 대시보드 수동 작업뿐이었음. 규정이 개정될 때마다 개발자가 콘솔에 들어가야 했고, **누가 언제 어떤 문서를 올렸는지 기록이 어디에도 남지 않았음**
  - `rag_documents` 신설(V6) + `GET·POST /api/admin/documents` · `DELETE /api/admin/documents/{id}`
  - 허용 형식이 **채팅 첨부와 반대** — 첨부는 비전 입력용이라 이미지만, 여기는 색인용이라 문서(PDF·TXT·MD·DOCX)만. 매직바이트는 PDF 만 검사함(txt·md 는 없고 docx 는 zip 이라 `PK` 만으로 구분되지 않음 — **검사할 수 없는 형식을 검사하는 척하지 않음**)
  - 최대 50MB. OpenAI 상한(512MB)에 맞추면 요청 하나가 멀티파트 버퍼를 512MB 잡아 단일 인스턴스가 그대로 멎음
  - **소프트 삭제** — 이 저장소에서 유일함. "언제 내려갔는가"가 감사 대상이라 행을 지우면 그 사실이 남지 않음. `uploaded_by` 도 `on delete restrict` 로, 사용자를 지워도 문서 이력이 사라지지 않음
  - 스토어 미설정이면 400 이고 **DB 행을 만들지 않음** — 어디에도 없는 문서가 목록에만 뜨는 상태가 가장 나쁨. Vector Store 연결 실패 시 올린 파일을 즉시 정리함
  - 목록은 `in_progress` 인 행만 상태를 다시 물음. 올린 사람 이름은 **조인으로 함께** 가져옴(N+1 방지)
  - 목업 모드에서도 전 경로 동작. 파일 ID 에 `mock-` 접두를 붙여 실 데이터와 섞이지 않게 함
- **관리자에 의한 비밀번호 초기화 (FEAT-ADMIN-003 · REQ-AUTH-006)** — 비밀번호를 잊으면 복구 경로가 전무했음. SMTP 도입 없이 관리자 발급으로 해결함
  - 임시 비밀번호는 응답에 **한 번만** 실리고 저장되지 않음. 혼동하기 쉬운 글자(`0/O` · `1/l/I`)를 뺀 문자 집합을 씀 — 사람이 눈으로 읽어 옮기는 값임
  - 자기 자신은 대상에서 제외 — 마이페이지에 변경 기능이 이미 있고, 관리자가 자기 세션을 스스로 끊을 이유가 없음

### Fixed
- **관리자 초기화에서 대상의 기존 토큰이 살아남던 것** — `password_changed_at` 을 초 단위로 자르는 기존 규칙은 "같은 초에 발급된 직전 토큰 1개"가 살아남는 틈을 감수하는데, 그 근거가 *"그 토큰의 주인은 방금 비밀번호를 바꾼 본인"* 이었음. **관리자 초기화에서는 그 전제가 깨짐** — 토큰 주인은 다른 사람이고 그 세션을 끊는 것이 기능의 목적임. 여기서는 살려 둘 토큰이 없으므로 경계를 현재 초의 끝으로 밀어 틈을 없앰
- **슬라이딩 재발급 검사 3건이 조용히 실행되지 않던 것** — 임계값이 클래스 단위 프로퍼티라 변형을 중첩 static 클래스로 두었는데, surefire 기본 include 패턴(`**/*Test.java`)에 걸리지 않아 수집조차 되지 않았음. 별도 파일로 분리함. 함께 넣었던 "중첩 클래스가 존재하는가" 검사는 아무것도 검증하지 못하는 가짜 통과였으므로 제거함
- **`frontend/src/lib/stream.test.ts` 의 fetch 스텁이 실물과 갈려 있던 것** — `{ ok, body }` 리터럴이라 `headers` 가 없었고, 응답 헤더를 읽는 코드가 붙는 순간 터졌음. 방어 코드를 넣지 않고 실제 `Response` 를 쓰도록 스텁을 고침

- **관리자 화면 (SCR-ADMIN-001 · 002)** — `/admin` 신설. 백엔드 API 만 있던 상태를 화면으로 마감함
  - **관리자에게만** 마이페이지에 진입점이 뜸. 노출 판단일 뿐 접근 제어가 아님 — URL 로 직접 들어오면 서버가 404 로 막음
  - 인덱싱 중인 문서가 하나라도 있을 때만 5초 폴링하고 **전부 종료 상태면 멈춤**. 안 멈추면 화면을 열어둔 내내 배경에서 돎
  - 실패 문서에 "답변 근거로 쓰이지 않습니다" 를 함께 적음 — 아이콘만 두면 "올라갔으니 됐다"고 읽힘(REQ-ADMIN-003)
  - 문서 0건은 "검색했는데 없다"가 아니라 **아직 시작하지 않은** 상태임을 문구로 밝힘
  - 삭제 확인이 "이미 나간 답변의 출처 표기는 그대로 남습니다"를 알림 — `citations` 가 영속화돼 있어 실제로 남고, 안 알리면 "지웠는데 왜 아직 보이지"가 됨
  - 임시 비밀번호 안내가 **두 사실을 함께** 알림 : 다시 볼 수 없다는 것과 대상자가 즉시 로그아웃된다는 것

## [2026-08-18]

### Added
- **첨부 미리보기 — 입력창 썸네일 카드 · 확대 보기 · 드롭/붙여넣기(FEAT-CHAT-001~003)** — ChatGPT · Claude 채팅 입력창과 같은 동작으로 맞춤. 종래에는 고른 파일이 아이콘 + 파일명 칩으로만 보여 **보내기 전에는 어떤 사진인지 확인할 수 없었음**
  - 카드는 **파일명 없이 썸네일만** 둠(파일명은 `alt` · `aria-label` 로만 남김)
  - **업로드 시점을 전송 → 선택 즉시로 옮김.** 백엔드 변경 없음 — `POST /api/files` 가 원래 `message_id=null` 로 저장하고 `DELETE /api/files/{id}` 와 고아 회수 크론이 이미 이 모델을 전제로 있었음. 업로드 책임이 `useChat` 에서 `Composer` 로 이동했고 `onSend` 가 `File[]` 대신 업로드가 끝난 첨부 목록을 받음
  - 올라가지 않은(업로드 중 · 실패) 첨부가 있으면 **보내기를 막음**. 막지 않으면 그 이미지가 빠진 채 나가는데 카드는 화면에 남아 있어 사용자는 갔다고 읽음
  - 카드 제거는 진행 중이면 `AbortController` 로 끊고 이미 올라갔으면 서버에서도 지움. 미리보기 objectURL 은 **카드 제거 · 전송 · 언마운트** 세 곳에서 회수함 — 눈으로 확인되지 않는 규칙이라 테스트가 회수 호출을 단언함
  - 확대 보기(`ImageLightbox`)는 전송 전 카드와 말풍선 썸네일이 **같은 컴포넌트**를 씀. 좌우 이동은 양 끝에서 순환하지 않고, 내려받기는 blob 으로 받아 저장함 — 백엔드가 다른 오리진이라 `<a download>` 는 브라우저가 무시하고 새 탭으로 엶
  - 드래그 오버레이는 진입/이탈을 세어 판정함. `dragleave` 만 보면 자식 요소를 지날 때마다 깜빡임
  - 확대 화면은 **핀치 줌**을 받음(1~4배 · 더블탭 1↔2배 · 확대 상태 끌기). 1배 아래로는 줄지 않고, 이미지를 넘기면 배율·위치를 초기화함 — 들고 가면 다음 장이 엉뚱한 곳에서 잘려 보임. 이미지에 `touch-action: none` 이 없으면 브라우저 기본 제스처가 먼저 먹어 핀치 이벤트가 오지 않음
