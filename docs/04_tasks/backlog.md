## 사용자 문의가 예상되는 미구현 항목 (기록용)

현재 요구 범위 **밖**이라 구현하지 않았지만, 실제 사용자가 붙으면 문의가 올 것들이다.
착수 결정 전까지는 기록만 둔다 — 판단이 필요할 때 여기서부터 보면 된다.

| 항목 | 지금 상태 | 문의 형태 | 착수 시 결정할 것 |
|------|-----------|-----------|-------------------|
| 비밀번호 재설정 | 없음. 잊으면 **복구 경로가 전무** | "비밀번호를 잊었어요" | 이메일 발송 수단(SMTP·외부 서비스) 선택 |
| 이메일 인증 | 없음. 아무 주소로나 가입됨 | 오타 주소 가입 후 "메일이 안 와요" · 스팸 가입 | 위와 같은 발송 수단이 전제 |
| 오류 관측 | `ErrorBoundary` 에 연결 지점만 있고 콘솔 기록뿐 | "화면이 하얘졌어요" 를 재현할 근거가 없음 | 관측 도구 선택 |
| 다중 인스턴스 | 레이트리밋·동시 스트림이 인메모리(단일 인스턴스 전제) | 스케일아웃 후 "상한이 안 걸려요" | 공유 저장소(Redis 등) 도입 여부 |
| 첨부 영속성 | 로컬 디스크. 볼륨 없으면 재시작마다 소실 | "어제 올린 사진이 사라졌어요" | 호스트 볼륨 vs `FileStorage` S3 구현 |
| 파일 URL 수명 | 서명 토큰 TTL 15분 | 페이지를 오래 열어둔 뒤 새로 그려지는 이미지가 깨질 수 있음 | TTL 연장 vs 만료 시 재발급 |
