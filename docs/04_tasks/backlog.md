## 사용자 문의가 예상되는 미구현 항목 (기록용)

현재 요구 범위 **밖**이라 구현하지 않았지만, 실제 사용자가 붙으면 문의가 올 것들이다.
착수 결정 전까지는 기록만 둔다 — 판단이 필요할 때 여기서부터 보면 된다. 지금 상태(무엇이 없는지 · 어떻게 버티는지)는 [overview](../02_architecture/overview.md) 「알려진 제약」 과 [features](../01_specs/features.md) 의 범위 밖 표가 정본이다.

| 항목 | 문의 형태 | 착수 시 결정할 것 |
|------|-----------|-------------------|
| 비밀번호 **셀프** 재설정 | "비밀번호를 잊었어요" | 이메일 발송 수단(SMTP·외부 서비스) 선택<br>**권장안(10-16)** : 직접 SMTP 대신 트랜잭션 메일 API 하나 + 1회용 재설정 토큰(짧은 TTL). 사용자가 적은 지금은 관리자 발급 유지 |
| 이메일 인증 | 관리자가 오타 주소로 발급한 뒤 "임시 비밀번호가 안 왔어요" | 위와 같은 발송 수단이 전제<br>**권장안(10-16)** : 셀프 재설정과 같은 발송 수단으로 함께 도입. 그 전까지는 관리자가 발급 전에 주소를 확인 |
| 오류 관측 | "화면이 하얘졌어요" 를 재현할 근거가 없음 | 관측 도구 선택<br>**권장안(10-16)** : 호스팅형 오류 수집 서비스의 무료 티어를 `ErrorBoundary` 연결 지점에 붙인다(자체 운영 도구는 단일 서버에 부담) |
| 다중 인스턴스 | 스케일아웃 후 "상한이 안 걸려요" | 공유 저장소(Redis 등) 도입 여부<br>**권장안(10-16)** : 단일 인스턴스 유지. 스케일아웃을 정할 때 Redis 를 함께 도입한다 |
| 첨부 영속성 | "어제 올린 사진이 사라졌어요" | 다중 인스턴스로 갈 때 `FileStorage` S3 구현<br>**권장안(10-16)** : 단일 인스턴스 동안 스냅샷 백업 유지. S3 는 위 다중 인스턴스 결정과 묶는다 |
| 파일 URL 수명 | 페이지를 오래 열어둔 뒤 새로 그려지는 이미지가 깨질 수 있음 | TTL 연장 vs 만료 시 재발급<br>**권장안(10-16)** : 만료 시 재발급. TTL 연장은 URL 이 로그에 남는 창(#105 §8)을 넓힌다 |
