# deploy.sh 의 .env 권한 프리플라이트 — 원격 스크립트 동작 확인
# 측정 시각: 2026-09-12T08:02:47Z
#
# 원격에서 도는 부분은 문자열이라 이스케이프가 한 칸 어긋나면 조용히 다르게 돈다.
# ssh_run 만 로컬 실행으로 바꿔 같은 문자열을 네 경우에 돌린다.
#
# **리눅스 컨테이너 안에서 돌린다.** 처음에 Git Bash(Windows/NTFS)에서 돌렸더니 chmod 가
# 먹지 않아 '고쳤다' 고 찍으면서 권한은 644 로 남았다 - 스크립트가 아니라 시험 환경의 문제였고,
# 그대로 믿으면 「통과」가 아니라 「모름」을 통과로 읽는 셈이 된다. 배포 대상과 같은 리눅스에서 다시 쟀다.

## 경우 1 - 둘 다 644. **고쳐야 정상**
  적용 전: 644 / 644
  .env 권한 644 -> 600 으로 고쳤다
  backend/.env 권한 644 -> 600 으로 고쳤다
  적용 후: 600 / 600

## 경우 2 - 이미 600. **건드리지 않아야 정상**
  .env 권한 600 (정상)
  backend/.env 권한 600 (정상)
  적용 후: 600 / 600

## 경우 3 - 한쪽이 없다. **경고만 내고 계속해야 정상**
  .env 권한 600 (정상)
  경고: backend/.env 가 서버에 없다 - compose 기동이 실패한다

## 경우 4 - 640(그룹 읽기 가능). **이것도 고쳐야 정상**
  적용 전: 640
  .env 권한 600 (정상)
  backend/.env 권한 640 -> 600 으로 고쳤다
  적용 후: 600

## 판정
  644·640 은 600 으로 고치고 무엇을 바꿨는지 찍는다. 이미 600 이면 건드리지 않는다.
  한쪽이 없으면 경고만 내고 죽지 않는다 - 권한 점검이 배포를 막는 단계가 되면 안 되기 때문이다
  (없는 것 자체는 그 뒤 compose 기동이 잡는다).
