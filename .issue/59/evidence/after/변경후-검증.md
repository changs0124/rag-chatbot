## CI 스텝을 추가하지 않았다

`npm run build` 가 `tsc -b` 를 타고, 그것이 `tsconfig.app.json` 을 탄다. **exclude 를 걷은 것만으로 CI 의 frontend 잡이 검사한다.** 없는 스텝을 만들지 않았다.

## 무엇을 어떻게 고쳤나

| 파일 | 변경 | 왜 |
|------|------|-----|
| `tsconfig.app.json` | `exclude` 줄 제거 | 테스트·`src/test/setup.ts` 까지 검사 대상에 넣음 |
| `ErrorBoundary.test.tsx` | `function Boom(): never` | 추론이 `void` 라 JSX 로 못 씀. **실제로 절대 반환하지 않으므로 `never` 가 사실에 맞는 표기** |
| `useChat.test.ts:181` | `onDone?.({ finishReason: 'stop', noSource: false })` | 정상 완료 케이스 |
| `useChat.test.ts:201` | `onDone?.({ finishReason: 'stop', noSource: true })` | 토큰이 안 왔으니 인용도 없음 — 서버라면 `noSource=true` 로 보냈을 상황 |

**`as any` 를 쓰지 않았다.** 타입만 맞추면 테스트가 실제 계약을 재현하지 못한 채로 남는다. 값은 서버가 그 상황에서 실제로 보낼 것(`ChatService:205` 의 `finishReason=stop`)을 썼다.

## `check-response-contract.sh` 를 지우지 않았다

이 게이트가 픽스처를 따로 보던 **이유의 절반**이 사라졌다. 그래도 남긴다.

```text
타입 검사   픽스처가 RagDocument 와 맞는지        → 이제 tsc 가 본다
이 게이트   그 타입이 백엔드 record · resultMap 과 맞는지 → tsc 는 못 본다
```

**서로 다른 것을 잡는다.** 그 근거를 스크립트 머리 주석과 `CONVENTIONS.md` 양쪽에 적었다. 지웠다면 백엔드↔프론트 필드 대조가 통째로 사라졌을 것이다.
