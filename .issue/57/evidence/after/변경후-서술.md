# 변경 후 — 서술이 실제와 같아졌다

## 1. 운영 로그 (가장 중요)

```text
- log.warn("대화 삭제 후 첨부 파일 정리 실패 - 행이 이미 없어 고아 회수 대상도 아님(영구 잔류). path={}")
+ log.warn("대화 삭제 후 첨부 파일 정리 실패 - 행이 없어 행 기준 회수는 못 보지만
+           저장소 스캔 회수가 다음 주기에 지움. path={}")
```

**"영구 잔류" 를 없앴다.** 로그를 읽는 사람이 손실로 오해해 없는 사고를 쫓지 않게 한다. 코드 옆에 왜 그렇게 적지 않는지도 주석으로 남겼다.

## 2. `ConversationService.delete` javadoc

행 기준 회수가 못 본다는 사실은 그대로 두고(참이다), **그 잔류를 무엇이 지우는지**를 이어 붙였다.

```text
+ <p><b>그 잔류는 저장소 스캔 패스가 지움</b> - FileService#cleanupUnreferencedFiles 가 파일 쪽에서
+ 돌며 가리키는 행이 없는 것을 회수하고, OrphanCleanupScheduler 가 매시 정각 2차 패스로 부름.
+ 즉 여기서 나는 경고는 영구 손실이 아니라 회수 대기임
+ (FileFlowTest.unreferenced_old_file_is_removed_by_scan 가 이 경로를 잠금).
```

**잠그는 테스트 이름을 적었다** — 다음 사람이 근거를 바로 찾는다.

## 테스트를 추가하지 않았다

완료 기준이 "회수가 실제로 도는지 테스트로 확인한다 — 없으면 추가한다" 였다. **이미 있었다.**

```text
FileFlowTest
  unreferenced_old_file_is_removed_by_scan   행만 지우고 → 파일이 회수됨
  referenced_file_is_kept_by_scan            행이 살아 있으면 안 지움
  fresh_unreferenced_file_is_kept_by_scan    방금 올라온 건 유예로 보호

$ ./mvnw -Dtest='FileFlowTest#…' test
tests="3"  failures="0"  errors="0"
```

**없는 케이스를 새로 만들어 숫자를 늘리지 않았다.** 이미 잠긴 것을 다시 잠그면 래칫만 올라가고 보호는 늘지 않는다.
