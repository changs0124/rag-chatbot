## 코드는 회수한다

`FileService.cleanupUnreferencedFiles` 가 저장소를 스캔해 **파일은 있는데 그것을 가리키는 행이 없는** 것을 지운다. `OrphanCleanupScheduler` 가 매시 정각 **2차 패스**로 부른다.

```java
// OrphanCleanupScheduler.cleanup()
// 2차 패스 - 행이 사라진 뒤 남은 파일은 위 행 기준 회수가 구조적으로 못 봄(2026-07-28 결정).
// 1차가 실패해도 돌게 try 를 나눔 - 둘은 서로 다른 잔류를 지움
int removed = fileService.cleanupUnreferencedFiles(cutoff);
```

## 실측 — 시나리오가 이미 테스트로 잠겨 있다

`FileFlowTest` 에 세 케이스가 있고, 첫째의 javadoc 이 정확히 이 상황을 적고 있다.

```java
/**
 * 대화 삭제 시 cascade 로 행이 먼저 사라진 뒤 파일 삭제가 실패하면, 행 기준 회수는 그 파일을
 * 구조적으로 볼 수 없음. 저장소 스캔 패스가 그 잔류를 지워야 함(2026-07-28 결정).
 */
void unreferenced_old_file_is_removed_by_scan()   // 행만 지우고 → 파일이 회수됨
void referenced_file_is_kept_by_scan()            // 행이 살아 있으면 안 지움
void fresh_unreferenced_file_is_kept_by_scan()    // 방금 올라온 건 유예로 보호
```

돌려 본 결과다.

```text
$ ./mvnw -Dtest='FileFlowTest#unreferenced_old_file_is_removed_by_scan+referenced_file_is_kept_by_scan+fresh_unreferenced_file_is_kept_by_scan' test
tests="3"  failures="0"  errors="0"
```

**회수는 실제로 돈다.** 완료 기준의 "없으면 테스트를 추가한다" 는 이미 있으므로 추가하지 않는다.
