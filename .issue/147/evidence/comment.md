## 무엇을 했나

공개된 데모 주소가 **동작하지 않는 상태임을 문서가 정확히 말하도록** 고쳤다. 원인이 달라 커밋을 둘로 나눴다.

| 커밋 | 내용 | 원인 |
|---|---|---|
| `docs:` | `README.md` · `frontend.md` 의 데모 서술 | 공개 전환으로 링크의 성격이 바뀌었다 |
| `docs(frontend):` | Vercel 스코프명 제거 | 보안 검토가 「검토 필요」로 올린 계정 식별자 |

## 문제 — 실측

```
$ curl -s -o /dev/null -w '%{http_code}' <데모 주소>
200                                      ← 사이트는 떠 있다

$ curl -s <데모 주소>/assets/index-*.js | grep -o 'http://localhost:8080' | wc -l
3                                        ← 번들이 자기 PC 의 8080 을 부른다
```

**화면은 뜨지만 로그인부터 실패한다.** 그런데 `README.md:45` 와 `frontend.md:191` 은 둘 다 "배포돼 있다"로 읽혔다.

비공개일 땐 나만 보는 메모였다. **공개 전환으로 방문자가 따라가는 링크가 됐고, 깨진 화면이 첫인상이 된다.**

`backlog.md` 가 이 상태를 이미 기록해 뒀지만 그건 **런칭 체크리스트 항목**이라, 저장소가 공개돼 이 링크가 남에게 보인다는 맥락은 빠져 있었다.

## 고친 방식

**링크는 지우지 않았다** — UI 완성도를 보여주는 값은 남기되, **누르기 전에 무엇을 보게 될지** 알 수 있게 했다.

`README.md` :

> **데모는 아직 백엔드가 연결되지 않았음** — \<주소\>
> 화면은 뜨지만 **로그인부터 실패함.** Vercel 에 `VITE_API_BASE_URL` 을 아직 넣지 않아
> 번들이 `http://localhost:8080` 을 부르기 때문임. UI 와 화면 전환만 볼 수 있음.
> 런칭 때 그 값을 넣고 재배포하면 풀림(절차는 `docs/04_tasks/backlog.md` 의 런칭 항목).

`frontend.md` 는 제목을 **"현재 배포" → "UI 미리보기(백엔드 미연결)"** 로 바꾸고, **재배포가 필요한 이유**(빌드 시점에 박히는 값이라 설정만 바꾸면 그대로다)를 덧붙였다.

**원인과 해소 조건을 함께 적었다** — 그냥 "동작 안 함"이라고만 쓰면 다음 사람이 원인을 다시 조사한다.

## 게이트가 내 실수를 잡았다

처음에 `` `docs/04_tasks/backlog.md` 「런칭」 `` 이라고 적었는데, **「런칭」은 헤딩이 아니라 목록 항목**이라 `check-doc-sections.sh` 가 실패했다. 섹션 참조 형식을 빼고 평문으로 가리키도록 고쳤다. 인용 블록 뒤 빈 줄 누락도 함께 잡았다.

## 코드를 건드리지 않은 이유

`VITE_API_BASE_URL` 은 이미 환경변수로 빠져 있고 `.env.example` 도 맞다. **배포 설정이 비어 있을 뿐**이고 그건 런칭 때 채운다 — 지금 코드를 고칠 것이 없다.
