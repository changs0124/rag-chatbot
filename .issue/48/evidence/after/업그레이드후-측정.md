## 이 작업의 실체는 "Boot 4 모듈 분해 따라가기" 였다

Boot 3 에서 `spring-boot-autoconfigure` 한 덩어리에 있던 자동설정이 기능별 모듈로 쪼개졌다. **의존성에 없으면 조용히 자동설정만 사라진다.** 컴파일은 통과하므로 런타임에 가서야 드러난다.

### Flyway — 가장 위험했던 함정

`flyway-core` 는 그대로 있는데 마이그레이션을 돌려 줄 **자동설정이 없어** 빈 스키마로 떴다.

```text
Caused by: org.postgresql.util.PSQLException: ERROR: relation "users" does not exist
[ERROR] Tests run: 184, Failures: 0, Errors: 126
```

**컴파일은 멀쩡히 통과했다.** 라이브러리가 클래스패스에 있기 때문이다. `spring-boot-starter-flyway` 로 바꿔 해결했다.

### 테스트 인프라

`@SpringBootTest` 가 `TestRestTemplate` 을 더 이상 자동 제공하지 않는다. 두 단계로 걸렸다.

1. `org.springframework.boot.test.web.client.TestRestTemplate` 가 없음 → `org.springframework.boot.resttestclient.TestRestTemplate` + `@AutoConfigureTestRestTemplate`
2. 그 자동설정이 `RestTemplateBuilder` 를 참조 → `spring-boot-restclient` 도 테스트 스코프로 필요
   (`ClassNotFoundException` 으로 컨텍스트 자체가 안 떠서 역시 126건이 죽었다)

**184건을 새 `RestTestClient` 로 갈아엎지 않았다.** 런타임 교체가 목적이지 테스트 재작성이 목적이 아니다.

## 손댄 파일과 이유

| 파일 | 무엇을 | 왜 |

| `AbstractPgIntegrationTest.java` | import 2줄 + `@AutoConfigureTestRestTemplate` | 위 |

**본문 로직을 고친 곳은 한 줄도 없다.** 전부 import·어노테이션·의존성 선언이다.

## 동작이 바뀐 지점

**없다.** 184건이 전부 같은 단언으로 통과하고 응답 계약도 일치한다.

## 검증되지 않은 경로 — 명시해 둔다

`OpenAiRealService` 의 SSE 파싱(`JsonNode` 13곳)은 **`APP_MODE=live` 전용이라 mock 테스트가 밟지 않는다.** Jackson 3 에서 `JsonNode.path()` 계열의 런타임 동작이 미묘하게 달라도 이 테스트 묶음으로는 드러나지 않는다.

- 확인한 것 : 컴파일 통과 · API 시그니처 동일 · 클래스 경로만 변경
- 확인하지 못한 것 : 실제 OpenAI SSE 스트림 파싱 동작
- 언제 확인되나 : 실 OpenAI 키가 생긴 뒤 백로그 「높은 우선순위」의 실 연동 항목에서

**이건 이 PR 이 만든 위험이 아니라 원래 mock 으로만 검증되던 경로다.** 다만 Jackson 교체가 그 경로를 지나가므로 적어 둔다.
