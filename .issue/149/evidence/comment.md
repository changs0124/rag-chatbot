## 무엇이 문제였나

`docs/CONVENTIONS.md` 「테스트·CI 게이트」가 실제 `scripts/check-*.sh` **9개 중 8개만** 이름으로 서술하고 있었다(`check-all.sh` 는 러너로 `:148` 에 따로). 빠진 것은 **`check-case-floor.sh`**.

**틀린 서술은 아니었다** — 래칫 규칙 자체는 `:98-99` 에 `case-floors.env` 기준으로 정확히 적혀 있었다. 빠진 것은 **그 규칙을 집행하는 스크립트가 목록에 없다**는 점이고, 그래서 게이트 목록을 훑는 사람이 이 게이트의 **존재와 한계**를 읽을 수 없었다.

## 고친 방식

다른 게이트와 **같은 형식**(「무엇을 보는가 / 못 잡는 것」)으로 항목을 넣었다.

**중복을 만들지 않았다** — 역할을 나누고 서로를 가리키게 했다 :

| | |
|---|---|
| 기존 `:98-99` | **언제 올리고 내리는가** — 사람이 지킬 규칙 |
| 신규 `:100-` | **무엇을 검사하는가** — 게이트의 동작 + 못 잡는 것 |

「못 잡는 것」에는 스크립트 머리주석이 이미 적어 둔 함정을 **요약해** 옮겼다(전문 복사 아님) :

- 수만 세므로 **단언을 지운 빈 테스트는 통과한다**
- **측정 입력이 낡으면 조용히 속는다** — 백엔드는 `target/` 의 옛 surefire XML 때문에 `clean` 후 재야 하고(2026-07-28 에 실제로 6건 부풀려졌다), 프론트는 이 스크립트가 `vitest-report.json` 을 읽기만 하고 만들지 않는다

## 왜 여태 안 보였나

`#136`·`#145` 에서 셸 게이트 둘을 추가하며 **같은 목록을 손댔는데도** 눈에 띄지 않았다. **게이트 목록의 완결성을 검사하는 게이트가 없기 때문**이고, `CONVENTIONS.md` 가 스스로 그 한계를 적어 두고 있었다 — "못 잡는 것 : … **버전이 아닌 목록형 서술(CI 잡 목록 · 이 게이트 목록 자체가 그렇다)**".

**그 게이트를 새로 만들지는 않았다.** 근거가 이 한 건뿐이고, 저장소가 이미 **"근거가 한 건뿐일 때 게이트를 만들지 않는다"(#55 기준)** 를 판단으로 남겨 두었다. 같은 누락이 한 번 더 나오면 근거가 둘이 된다.
