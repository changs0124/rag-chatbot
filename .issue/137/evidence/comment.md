## 무엇을 했나

공개 전환으로 전제가 바뀐 세 곳의 **근거를 갱신했다.** 결론은 뒤집지 않았다.

| 위치 | 옛 전제 | 왜 성립하지 않나 |
|---|---|---|
| `scripts/deploy.sh:5` | GHCR 은 패키지 저장 500MB · 전송 1GB/월 한도에 걸린다 | 공개 패키지는 저장·전송이 무료 |
| `docs/02_architecture/backend.md:430` | 같은 근거의 문서판 | 위와 같음 |
| `docs/02_architecture/frontend.md:202` | Vercel 연결에 GitHub App 설치 승인이 필요 | 공개 저장소는 별도 접근 승인이 없음 |

## 결론을 유지한 이유

**이미지는 여전히 `docker save` → `scp` → `docker load` 로 옮긴다.** 한도 말고도 근거가 있기 때문이다 :

- 배포 서버가 1GB 급이라 **거기서 빌드할 수 없다**
- 서버가 하나뿐이라 레지스트리의 이점(여러 대에 같은 이미지를 뿌리는 것)을 **쓸 데가 없다**
- 토큰 · 태그 관리 · 정리 정책이 따라붙지 않는다
- 압축 90MB 를 한 번 넘기는 편이 단순하고, GCP 인바운드 전송은 무료다

**근거만 갱신했다.** 한도 논리를 통째로 지우면 다음 사람이 "이유 없이 이렇게 돼 있네" 하고 바꾼다. 무엇이 **왜 더는 성립하지 않는지**를 남겨야 그 다음 판단이 제대로 된다.

## #135 와 겹치지 않는다

`docs/CONVENTIONS.md:126` 과 `scripts/check-all.sh:5` 도 같은 단어를 쓰지만 저쪽은 **Actions 분(minutes) 한도** 근거라 #135 의 몫이다. 이 PR 은 **패키지 한도와 연결 권한**만 건드린다 — 파일이 겹치지 않아 병렬로 진행했다.

## 손대지 않은 것

`CHANGELOG.md` 의 #127 항목("비공개 패키지는 저장 500MB · 전송 1GB/월 한도가 걸리는데")은 **그대로 둔다.** 당시 상황의 이력 서술이라 지금도 맞는 값이다 — #133 에서 `/home/User/deploy` 를 남긴 것과 같은 판단이고, `check-doc-versions.sh` 가 `docs/06_changelog/**` 를 일부러 제외하는 것과도 같은 이유다.
