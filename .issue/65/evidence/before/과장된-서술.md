# 변경 전 — 주석이 실제보다 많이 말한다

측정 커밋 : `origin/main` (`860e7bc`)

## 1. `useChat.test.ts` — 값이 테스트를 가르는 것처럼 읽힌다

```text
:181  // 서버가 실제로 보내는 done 페이로드와 같은 모양임(ChatService: finishReason=stop + noSource)
:182     onDone?.({ finishReason: 'stop', noSource: false })
:202  // 토큰이 하나도 안 왔으니 인용도 없음 - 서버라면 noSource=true 로 보냈을 상황임
:203     onDone?.({ finishReason: 'stop', noSource: true })
```

**그런데 실제 핸들러는 인자를 받지 않는다.**

```ts
// useChat.ts:178
onDone: () => {
  patch((m) => ({ ...m, status: 'complete' }))
  refreshConversations()
},
```

`noSource` 도 `finishReason` 도 훅 어디에서도 읽지 않는다(`grep -rn "noSource" src/` — 훅 로직에 참조 없음). 즉 **두 케이스에 다른 값을 넣었지만 단언 결과는 그 값과 무관하다.**

값 자체는 서버가 보낼 것과 맞다. 문제는 주석이 "이 값이 이 테스트에서 의미를 갖는다" 는 인상을 준다는 것이다.

**지금 해는 없다.** 다만 `noSource` 가 나중에 무자료 배너 같은 실제 분기에 쓰이면 **이 두 케이스는 그 분기의 회귀를 못 잡은 채 통과한다.**

## 2. `check-doc-sections.sh` — "못 잡는 것" 목록이 불완전하다

머리 주석이 사각을 넷 적었다(같은 문서 안 · 별명 · 강조 · changelog). **다섯째가 빠졌다.**

```text
docs/02_architecture/backend.md:222
  … [features.md](../01_specs/features.md) FEAT-ADMIN-002 「soft delete 를 쓰는 이유」에 있다.
                                           ^^^^^^^^^^^^^^^ 이것 때문에 수집에서 빠짐
```

PATTERN 이 파일 참조와 `「` 사이에 **공백만** 허용한다. 텍스트가 끼면 **조용히 빠진다.**

확인했다.

```text
$ grep -noE '(\[…\]\(…\.md…\)|`…\.md`)[[:space:]]*「.*' docs/02_architecture/backend.md
95:`api.md` 「API 목록」
201:[overview](./overview.md) 「알려진 제약」
                                              ← 222 행이 없다
```

**로케일 버그와 같은 실패 모드다** — 경고 없이 대상에서 사라진다. 그 게이트를 만들 때 정확히 그 함정을 한 번 밟았고, 머리 주석에 사각을 적는 이유가 그것이었는데 이 케이스를 빠뜨렸다.

## 넓히면 오탐이 난다

대상인 `soft delete 를 쓰는 이유` 는 **헤딩이 아니라 굵은글씨**다.

```text
docs/01_specs/features.md:302
**soft delete 를 쓰는 이유** : "언제 내려갔는가"가 감사 대상이다(REQ-ADMIN-002). …

$ grep -nE "^#{1,6} .*soft delete" docs/01_specs/features.md
(헤딩 아님)
```

즉 **「…」 가 섹션이 아니라 굵은 라벨을 가리키는 다섯째 갈래**다. 잡으려면 `has_section()` 도 굵은글씨를 보도록 넓혀야 하고, 그건 별개의 설계 판단이다.
