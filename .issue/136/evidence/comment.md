## 무엇을 했나

`scripts/check-shell-syntax.sh` 를 추가해 **추적되는 셸 전부에 `bash -n`** 을 돌린다. `check-all.sh` 와 CI `static` 잡 양쪽에서 **제일 먼저** 돈다.

## 왜 필요했나

이 저장소의 품질 게이트는 `scripts/check-*.sh` 가 만든다. 그런데 정작 **그 스크립트들을 보는 게이트가 하나도 없었다** — 게이트를 만드는 코드가 아무 게이트도 받지 않는 상태였다. `#133` 에서 `deploy.sh` 를 고치는 동안 드러났고, `#138` 의 버그가 살아남은 것도 같은 공백 때문이다.

`deploy.sh` 는 특히 위험하다 — `backlog.md:27` 기준 **통짜로 실행된 적이 없어** 구문 오류가 실제 배포를 시도하는 순간에야 드러난다.

## 설계 판단 셋

**① 목록을 손으로 관리하지 않는다** — `git ls-files` 로 산출한다. 상수로 개수를 박으면 스크립트를 하나 더할 때마다 같이 고쳐야 하고, 안 고치면 **새 파일만 조용히 빠진다.** 게이트가 막으려던 상황이 게이트 안에서 재현된다. 대신 **검사한 개수를 출력**해 대상이 0이 되어도 "통과"로 보이지 않게 했다.

**② `case-floors.env` 를 포함한다** — `.sh` 가 아니지만 `check-case-floor.sh:19` 가 `.` 으로 읽는다. 여기 구문 오류가 나면 그 게이트가 통째로 깨진다.

**③ 제일 앞에 둔다** — 뒤따르는 검사들이 전부 셸이라, 하나가 깨지면 그 검사만 죽고 나머지는 통과해 **부분적인 초록불**이 나온다. 앞에 두면 "검사가 깨졌다"와 "검사가 잡아냈다"가 구분된다. `static` 잡 이름도 함께 갱신했다(스텝을 더하면 이름이 낡는다).

## 검증

| 완료 기준 | 결과 |
|---|---|
| 스캔 건수가 `git ls-files` 와 일치 | **9개 = 9개** (셸 8 + `case-floors.env`) |
| **일부러 깨뜨리면 실패하는가** | `구문 오류 : scripts/check-doc-refs.sh` + 줄번호 + `exit 1`. 되돌리면 통과 |
| `check-all.sh docs` 에서 돈다 | ✓ (조기 종료보다 앞) |
| CI 에서도 돈다 · 스텝 이름으로 드러난다 | `static` 잡의 두 번째 스텝 |
| 기존 잡 동작 불변 | 7잡 그대로 |

**게이트가 만들어지자마자 일을 했다** — 이 작업 중 내가 쓴 CHANGELOG 문장이 `check-doc-refs.sh` 에 걸렸다. 정규식 문자 클래스의 대괄호 둘을 옵시디언 위키링크로 읽은 것이라, 표현을 바꿔 통과시켰다.

## shellcheck 도입 비용 측정 (범위 밖, 별건 판단용)

완료 기준이 요구한 측정이다. v0.10.0 으로 기존 8개를 돌린 결과 **총 12건** :

| 심각도 | 건수 |
|---|---|
| error | **1** |
| warning 이상 | 1 |
| info 이상 | 12 |

11건은 `info`(따옴표 · `ls` 사용 · 도달 불가 코드 등)다. 유일한 `error` 는 `check-doc-versions.sh:109` 의 **SC1087** 인데, 정규식 문자 클래스가 붙은 `$name` 을 배열 첨자로 오독한 것이라 **동작은 정상**이다(CI 가 계속 통과해 왔다). 중괄호로 표기만 명확히 하면 사라진다.

**즉 도입 비용이 작다** — 12건 중 실제 결함은 0건이고, 새로 추가한 `check-shell-syntax.sh` 자체는 **경고 0건**이다. 도입 판단은 이 수치를 근거로 별건에서 하면 된다.

## `bash -n` 이 못 잡는 것

구문이 맞으면 통과한다. `#138` 의 버그(`printf` 가 인자를 버리던 것)가 정확히 그 예다 — `bash -n` 통과, `shellcheck` 만 SC2183 으로 잡았다. 이 한계를 `CONVENTIONS.md` 의 게이트 목록에 명시했다.
