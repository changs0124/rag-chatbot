   130	
   131	- **단일 인스턴스 전제** — 레이트리밋·동시 스트림 카운터가 인메모리라 다중 인스턴스에서는 상한이 인스턴스 수만큼 늘어난다. 수평 확장 시 공유 저장소가 필요하다.
   132	- **레이트리밋 키 축출 = 카운터 리셋** — 키 총량 상한을 넘으면 가장 오래 안 쓴 키부터 버려지므로, 그 사용자의 카운터가 초기화된다.
   133	- **로그인 실패 상한은 남의 계정을 잠그는 지렛대가 된다.** 키가 정규화된 이메일(IP 아님)이라 알려진 주소로 일부러 틀리면 그 주인이 그 분 동안 429 를 받고, 여러 계정을 훑는 살포형 시도는 걸리지 않는다. 단일 인스턴스 전제에서 감수한 한계다(`RateLimiterService.acquireLoginAttempt`).
   134	- **Spring Boot 4.1 트랙이다**(#48). 4.1 의 OSS 지원은 **2027-07** 까지다(재판단은 backlog).
   135	- **`V3` 이전에 저장된 중단 답변**은 정상 완료분과 구분할 표시가 없다(소급 보정하지 않음).
   136	  `V4` 이전 메시지의 토큰 사용량도 마찬가지로 복원할 수 없어 비워 둔다. 근거는 [erd.md](../01_specs/erd.md) 「설계 원칙」.
   137	- **업스트림이 멎으면 그 스트림의 자원은 읽기 타임아웃까지 잡혀 있다.** `app.openai.stream-read-timeout-ms`
   138	  (기본 9분)가 SSE 타임아웃(10분)보다 짧도록 기동 시 강제되므로 **워커가 emitter 보다 오래 살지는
   139	  않지만**(#76·#92), 워커의 블로킹 read 는 인터럽트로 깨지지 않아 그 시간만큼은 스레드와 동시 스트림
   140	  권한이 함께 잡힌다. 전역 상한(`CHAT_MAX_CONCURRENT_STREAMS`, 값은 [backend](./backend.md) 「유량 제어」) 중 한 자리가 그만큼 줄어든다.
   141	- **타임아웃 시 클라이언트에 종료 이벤트가 가지 않는다.** emitter 가 닫힌 뒤에는 `done`·`error` 를
   142	  실을 수단이 없다. 받는 쪽이 종단 이벤트 없는 종료를 처리해야 하며, 프록시·네트워크 절단도 같은
   143	  모양으로 도착한다.
   144	- **업로드는 파일 전체를 힙에 올린다.** `MultipartFile.getBytes()` 라 크기 검사(10MB)를 통과한 파일이 통째로 오른다.
   145	  크기는 **올리기 전에** `getSize()` 로 본다(첨부 #402) — 멀티파트 한도(26MB)까지의 파일은 디스크 임시 파일에 머문 채 400 이다.
   146	  그래서 사용자 한 명의 동시 업로드가 잡는 힙은 분당 상한(#95, 30) × 10MB ≈ 300MB 로 묶인다. 상한이 사라지지는 않으며,
   147	  스트리밍 저장으로 바꾸는 것은 원인이 다른 별건이다. 관리자 문서 업로드도 같은 원칙이다(#453, 상한 25MB — 위 사용자 힙 계산과는 별개).
   148	- **첫 관리자의 임시 비밀번호는 바꾸기 전까지 계속 유효하다.** 「한 번만 찍는다」가 「한 번만
   149	  유효하다」를 뜻하지는 않는다 — 변경을 강제하는 플래그가 없다. 로그는 회전시켜 잔류 창을 줄였지만
   150	  (10MB×3), 회전 전에 그 로그를 읽을 수 있는 사람은 관리자 계정을 얻는다. 첫 로그인 후 즉시 변경할 것.
   151	- **첨부 서빙 토큰은 비밀번호 변경으로 무효화되지 않는다.** 최대 TTL(`FILE_ACCESS_TOKEN_TTL_MINUTES`) 동안 이미 발급된
   152	  URL 이 열려 있다(#104). 기준선을 태우면 이미지 요청마다 DB 조회가 붙고 정상 사용자의 열린 화면도
   153	  깨지므로 감수한 트레이드오프다. 근거는 [backend](./backend.md) 「인증」에 있다.
   154	- **관리자 명단 변경에 재기동이 필요하다.** 앱에 권한 상승 API 를 두지 않은 대가다.
   155	- **도메인 검사는 계정을 만드는 시점에만 한다** — 정책 도입 이전에 만들어진 도메인 밖 계정은 로그인이
   156	  계속 된다. 치우려면 계정 삭제 기능이 필요한데 없다.
   157	- **사용량 집계 화면이 없다.** `messages` 에 기록만 하며 조회는 DB 직접 질의뿐이다.
   158	- **첨부는 로컬 디스크에 있다.** compose 의 `uploads` 볼륨이 받으며, 볼륨을 떼거나 디스크를 잃으면 마지막 스냅샷(아래, 매일) 이후 분은 소실된다.
   159	- **자체 호스팅이라 전원 · 네트워크 · OS 를 직접 진다.** 서버가 꺼지면 서비스가 멈춘다. 백업은
   160	  Lightsail 자동 일일 스냅샷(최근 7개)이다(#243). 디스크 통째로만 복구되고 오프사이트가 아니다. 백업 · 복구 절차와 전환 조건은
   161	  [backend](./backend.md) 「배포」에 있다.
   162	- **관측 도구가 없다.** 장애 재현 근거가 상관 ID(REQ-OPS-002) 뿐이며 도구 도입은 별건이다.
   163	- **OpenAI Vector Store 는 저장 용량 비례 과금**이라 문서가 늘면 월 비용이 선형으로 는다.
   164	- **모델은 `OPENAI_MODEL` 하나로 바뀐다**(값은 위 「외부 연동」). 다른 계열로 바꾸면 인용 표기 처리(#277 · #281)가 전제와
   165	  어긋나므로, 바꾼 뒤에는 `live-integration.md` 의 QA 를 다시 잰다.

   613	### 데모 - 로컬 + 터널
   614	
   615	프론트는 Vercel(https)에 있고 백엔드는 로컬이므로 `http://공인IP:8080` 직결은 성립하지 않는다 —
   616	https 페이지가 http 를 부르면 브라우저가 mixed content 로 막는다. 터널이 https 종단을 대신 맡는다.
   617	
   618	1. 백엔드를 평소대로 띄운다(`./mvnw spring-boot:run`, `:8080`).
   619	   **이 경로는 `backend/.env` 를 읽지 않는다** — dotenv 로더가 없어 환경변수를 셸에 직접 넣어야 한다.
   620	   `.env` 를 그대로 쓰려면 `docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build db app`
   621	   으로 띄운다 — 본체에는 `build` 가 없어 override 를 겹쳐야 로컬 빌드가 성립한다(#127)
   622	2. 터널을 연다 — `ngrok http 8080` 또는 `cloudflared tunnel --url http://localhost:8080`
   623	3. 백엔드 `ALLOWED_ORIGINS` 에 **Vercel 도메인**을 넣는다. 터널 주소가 아니다 —
   624	   이 값은 백엔드의 공개 주소가 아니라 **요청을 보내는 화면의 출처**다
   625	4. Vercel `VITE_API_BASE_URL` 에 **터널 주소**를 넣고 재배포한다
