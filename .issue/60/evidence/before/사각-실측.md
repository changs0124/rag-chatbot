# 변경 전 — 섹션 이름을 아무도 안 본다

측정 커밋 : `origin/main` (`966a4a1`)

## 사각

`scripts/check-doc-refs.sh` 는 머리 주석대로 **경로의 실재**만 본다. #28 에서 `backend.md` 가 `frontend.md` 의 없는 섹션(「데이터·오류」)을 가리켰는데 게이트가 통과했고 사람이 눈으로 찾았다.

`check-doc-versions.sh`(#52)는 **버전 주장**을 본다 — 원인이 다르다. 그쪽은 *낡은 값*, 이쪽은 *깨진 참조*다.

## 「…」 를 전수 조사했다 — 전부 섹션 참조가 아니다

문서에 25건 있고 네 갈래로 갈린다.

```text
① 파일 참조가 붙은 것 — 검사 가능
   frontend.md:174   `backend.md` 「배포」
   backend.md:201    [overview](./overview.md) 「알려진 제약」

② 같은 문서 안 — 대상 파일이 없다
   api.md:107        "이 표 아래 「API 목록」"

③ 경로가 아니라 별명 — 해석 불가
   features.md:142   "백로그 「파일 URL 수명」"

④ 섹션이 아니라 그냥 강조 — 오탐의 원천
   live-integration.md 「자료 없음」 (5건)   ← UI 배너 이름이다
```

**①만 검사한다.** #52 와 같은 판단이다 — 넓게 잡으면 오탐이 쏟아지고, 시끄러운 게이트는 무시당해 없는 것과 같아진다.

## 표기 차이 둘을 미리 확인했다

```text
api.md        헤딩에 번호를 매긴다 : `## 2. API 목록`      ← 참조는 「API 목록」
frontend.md   헤딩에 접미가 붙는다 : `## 배포 (Vercel)`     ← 참조는 「배포」
```

정확 일치만 보면 **둘 다 오탐**이다. 백로그가 경고한 "헤딩 표기가 문서마다 일정한지 먼저 확인해야 한다" 가 이것이었다.

## 파일명 해석 규칙이 필요하다

```text
backend.md:51   `frontend.md`   → 같은 폴더(docs/02_architecture/)  ✓
backend.md:95   `api.md`        → 다른 폴더(docs/01_specs/)         ✗ 같은 폴더 규칙으로는 못 찾음
```

`docs` 안 `.md` 파일명에 **중복이 없음**을 확인했으므로, 같은 폴더에 없으면 파일명이 유일한 것으로 해석한다. 여럿이면 해석하지 않는다.

## 어디서 돌릴까 — `docs` 잡

```yaml
docs:
  steps:
    - uses: actions/checkout@v4
    - run: bash scripts/check-doc-refs.sh    # JDK · Node 셋업 없음
```

이 검사는 파일만 읽으면 되므로 maven 이 필요 없다(#52 와 다른 점이다). **그래서 grep 기반 순수 bash 로 쓴다** — `check-doc-refs.sh` 가 "grep 기반(어디서나 실 바이너리)" 이라고 적어 둔 것과 같은 제약을 지킨다.
