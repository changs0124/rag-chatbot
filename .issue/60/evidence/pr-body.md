관련 이슈 #60

## 결론

`scripts/check-doc-sections.sh` 를 만들어 `docs` CI 잡에 붙였다. **#28 사례를 재현해 잡는 것**을 확인했고, 만드는 중에 **조용한 버그를 하나 더 잡았다.**

## 합격선 — 재현

```text
### backend.md 가 frontend.md 의 없는 섹션을 가리키게 되돌림 (#28 사례)
FAIL: docs/02_architecture/backend.md:51 — docs/02_architecture/frontend.md 에 「데이터·오류」 헤딩이 없음
      있는 헤딩: … · API 통신 · 채팅 스트림 수신 · … · 배포 (Vercel) · …

### 없는 파일을 가리키면
FAIL: docs/CONVENTIONS.md:20 — 참조한 파일을 찾지 못함: './02_architecture/nope.md'
```

**있는 헤딩 목록을 함께 준다** — 오타인지 이름이 바뀐 건지 바로 판단된다. 정상 상태에서는 **16건 대조 · 오탐 0**.

## 만드는 중에 조용한 버그를 잡았다

처음 패턴은 `「[^」]+」` 였다. **로케일이 `C` 인 환경에서 grep 은 멀티바이트를 바이트로 다룬다.** `」`(E3 80 8D)를 부정 문자클래스에 넣으면 그 바이트가 다른 한글에도 들어 있어 — `데`(EB **8D** B0) — 멀쩡한 줄이 매칭에서 빠진다.

```text
[처음 패턴] #28 사례를 넣고 실행
  섹션 참조 13 건 대조
  섹션 참조 검사 통과     ← 잡지 못하고 초록. 대상이 14 → 13 으로 줄었을 뿐이다
```

**이 저장소가 가장 싫어하는 형태다** — 조용히 통과하고, 통과했다는 사실조차 숫자로만 드러난다. 게이트를 만들면서 게이트가 새는 것을 넣을 뻔했다.

줄 끝까지 잡고 섹션 이름은 **셸 파라미터 확장**(`${text#*「}` · `${section%%」*}`)으로 잘라내도록 바꿨다. 바이트 안전하고 로케일에 기대지 않는다. **고치자 대상이 14 → 16건으로 늘었다** — 원래 빠져 있던 `CONVENTIONS.md:57` 과 `README.md:44` 다.

## 「…」 가 전부 섹션 참조는 아니다

25건을 전수 조사하니 네 갈래였다.

```text
① 파일 참조가 붙은 것  `backend.md` 「배포」 · [overview](./overview.md) 「알려진 제약」   ← 검사
② 같은 문서 안        "이 표 아래 「API 목록」"                                        ← 제외
③ 경로가 아니라 별명   "백로그 「파일 URL 수명」"                                       ← 제외
④ 그냥 강조          「자료 없음」(UI 배너 이름, 5건)                                  ← 제외
```

**①만 검사한다.** #52 와 같은 판단이다 — 넓게 잡으면 오탐이 쏟아지고, 시끄러운 게이트는 무시당해 없는 것과 같아진다.

## 표기 차이 둘을 흡수한다

```text
api.md        `## 2. API 목록`    ← 번호 접두를 벗겨서 비교
frontend.md   `## 배포 (Vercel)`  ← 헤딩이 섹션 이름으로 시작하면 통과
```

정확 일치만 봤다면 **둘 다 오탐**이었다. 백로그가 경고한 "헤딩 표기가 문서마다 일정한지 먼저 확인해야 한다" 가 이것이었다.

## `docs` 잡에 붙였다

이 검사는 파일만 읽으면 되어 maven 이 필요 없다(#52 와 다른 점). **grep 기반 순수 bash 로 썼다** — `check-doc-refs.sh` 가 "grep 기반(어디서나 실 바이너리)" 이라고 적어 둔 제약을 그대로 지킨다.

## 못 잡는 것을 머리 주석에 적었다
