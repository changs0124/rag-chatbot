# 변경 전 — Jackson 3 의 동작 차이를 실측한다

측정 커밋 : `origin/main` (`7fbcd7f`) · 프로덕션 코드 무수정
방법 : 프로젝트 실 클래스패스(`jackson-databind 3.1.5` · `jackson-core 3.1.5`)로 독립 JVM 프로브

## 실측 — 두 가지가 바뀌었다

```text
missing.asText()    = []        Jackson 2 와 동일
string.asText()     = [hi]      동일
null.asText()       = []        Jackson 2 는 "null" (문자열!) 이었다
OBJECT.asText()  -> THROW tools.jackson.databind.exc.JsonNodeException
ARRAY.asText()   -> THROW tools.jackson.databind.exc.JsonNodeException
OBJECT.asText("D")  = [D]       기본값을 주면 안 던진다
```

**(a) Object/Array 에 기본값 없이 부르면 던진다.** **(b) JSON null 이 `"null"` → 기본값.**

#48 커밋 메시지의 **"`ObjectMapper`·`JsonNode` API 는 그대로"** 는 시그니처에 대해서만 참이었다. 그래서 컴파일이 조용히 통과했다.

## `asText` 는 deprecated 이고 `asString` 이 대체다

```text
$ javac -Xlint:deprecation …
warning: [deprecation] asText() in JsonNode has been deprecated

asString("") on OBJECT  = []     ← Jackson 2 의미론 그대로
asString("") on MISSING = []
asString("") on NULL    = []
asString("") on STRING  = [hi]
asString(null) on NULL    = null  ← :389 가드의 전제가 유지된다
asString(null) on MISSING = null
deprecation 경고 0건
```

## (a) 가 닿는 6곳 — 기본값 없음

```text
OpenAiRealService.java:242   ev.path("type").asText()        가드 없음 — 모든 SSE 이벤트마다
                      :244   ev.path("delta").asText()       type == response.output_text.delta
                      :302   item.path("type").asText()      output[] 순회
                      :304   r.path("filename").asText()
                      :312   ann.path("type").asText()
                      :313   ann.path("filename").asText()   :312 가 file_citation 확인 뒤
```

**`:242` 가 제일 나쁘다.** 가드가 없고 모든 이벤트에서 돈다. 예전에는 모르는 모양의 이벤트가 와도 `if/else` 사슬을 빠져나가 무해하게 무시됐는데, 지금은 예외가 `ChatService:216` 까지 올라가 **스트림이 통째로 죽는다.**

## 터진다 vs 터질 수 있다 — 정직하게 적는다

**지금 터진다는 근거는 없다.** 여섯 줄 전부 OpenAI Responses API 가 문자열을 주는 필드이고, 문서화된 응답 모양 중 Object/Array 를 넣는 것은 없다. `:244`·`:313` 은 타입 가드 뒤에 있다.

현실적 시나리오는 **API 스키마 드리프트 · 프록시가 끼워 넣는 오류 봉투 · 호환 엔드포인트**(`app.openai.base-url` 로 갈아끼울 수 있다) 정도이고 전부 가정이다.

**즉 이것은 *실패 태도의 변화*지 알려진 트리거가 있는 버그가 아니다.**
