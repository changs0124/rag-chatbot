## 설계 판단 셋

### 1. `docs` 잡이 아니라 `backend` 잡에 붙였다

`docs` 잡은 checkout 과 bash 뿐이다. 그런데 **JUnit 은 `pom.xml` 에 없고 Spring Boot BOM 이 관리한다.**
`docs` 잡에 붙였으면 **정작 잡아야 할 것을 못 잡았다.** `backend` 잡은 이미 `./mvnw -B verify` 로 m2 를
채우므로 BOM pom 을 파일로 읽으면 된다 — maven 을 다시 실행하지 않는다.

### 2. 전수 검사 대신 선언한 이름만 본다

문서의 모든 숫자를 훑으면 오탐이 쏟아진다(산문 속 예시, 날짜, 이슈 번호). **게이트가 시끄러우면
사람들이 무시하게 되고, 그러면 없는 것과 같다.** 스크립트 안의 표에 있는 이름만 본다. 대상을 늘리려면
표에 줄을 추가한다.

### 3. 접두 일치로 비교한다

문서는 메이저만 적기도 한다.

```text
문서 4.1  실제 4.1.1   → 통과   (overview.md 의 mermaid 노드가 이렇게 적혀 있다)
문서 19   실제 19.2.7  → 통과
문서 5    실제 6.0.3   → 실패   ← 오늘의 사례
```

**긴 이름을 먼저 매칭한다.** `React` 를 앞에 두면 `React Router 8` 을 `React 8` 로 읽어 오탐이 난다.
재현 3번이 이 순서를 잠근다.

## 구현 중 걸린 것

`pom.xml` 들여쓰기가 **탭**이라 `tr -d '\r\n'` 으로 개행만 지우면 태그가 붙지 않아 `<artifactId>X</artifactId><version>` 패턴이 매칭되지 않았다. `tr -d '\r\n\t '` 로 여백까지 지워 해결했다.
