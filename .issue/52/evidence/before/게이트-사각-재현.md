# 변경 전 — 사각을 실측한다

"게이트가 없었다" 를 주장이 아니라 **재현으로** 남긴다.

## 조작

`docs/INDEX.md:16` 을 #51 이전 상태(`JUnit 5`)로 되돌린다. 실제 해석되는 버전은 `6.0.3` 이므로 **명백히 거짓인 문서 상태**다.

```text
| 테스트 | 백엔드 JUnit 5 + Testcontainers(실 PostgreSQL) · 프론트 Vitest + Testing Library |
                  ^^^^^^^ 실제 6.0.3
```

```text

```

**거짓인 문서를 아무도 막지 못한다.** #51 이 이 상태로 main 에 들어갔던 이유가 정확히 이것이다.

## 각 게이트가 실제로 보는 것

스크립트를 읽고 확인했다.

| 게이트 | 검사 대상 | JUnit 표기를 보나 |
|--------|-----------|-------------------|
| `check-doc-refs.sh` | 문서가 가리키는 **경로의 실재** · 볼트 위키링크 잔존 | 안 봄 |
| `check-runtime-versions.sh` | `.nvmrc` · `engines.node` · `pom.xml` 의 `java.version` **두 런타임만** | 안 봄 |
| `check-response-contract.sh` | `DocumentResponse` 의 **필드 이름** 4곳 | 안 봄 |
| `check-case-floor.sh` | **케이스 수** 하한 | 안 봄 |

`check-runtime-versions.sh` 가 가장 가깝지만 Java·Node 로 범위가 못박혀 있어 프레임워크·라이브러리는 대상이 아니다.

## 설계 제약 — `docs` CI 잡에는 maven 이 없다

```yaml
docs:
  name: docs (참조 실재)
  steps:
    - uses: actions/checkout@v4
    - run: bash scripts/check-doc-refs.sh
```

JDK·Node 셋업 스텝이 없다. 그런데 **JUnit 버전은 `pom.xml` 에 적혀 있지 않고 Spring Boot BOM 이 관리한다.** 즉 새 검사를 `docs` 잡에 붙이면 **정작 잡아야 할 것을 못 잡는다.** `backend` 잡(JDK 17 + maven 캐시 + `./mvnw -B verify`)에 붙여야 한다.
