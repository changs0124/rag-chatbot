변경 후 — 환경변수를 하나도 주지 않고 실행

$ bash scripts/deploy.sh
배포 대상이 지정되지 않았다. 아래 환경변수를 넣고 다시 실행할 것 :
  - DEPLOY_HOST(인스턴스 이름)
  - DEPLOY_ZONE(영역)
  - DEPLOY_PROJECT(GCP 프로젝트)
  예) DEPLOY_HOST=… DEPLOY_ZONE=… DEPLOY_PROJECT=… bash scripts/deploy.sh --dry-run
$ echo $?
2

$ bash scripts/deploy.sh --dry-run        ← 이쪽이 핵심이다
배포 대상이 지정되지 않았다. 아래 환경변수를 넣고 다시 실행할 것 :
  - DEPLOY_HOST(인스턴스 이름)
  - DEPLOY_ZONE(영역)
  - DEPLOY_PROJECT(GCP 프로젝트)
  예) DEPLOY_HOST=… DEPLOY_ZONE=… DEPLOY_PROJECT=… bash scripts/deploy.sh --dry-run
$ echo $?
2

--dry-run 도 똑같이 막힌다. 검사를 preflight 안에 뒀다면 이 경로는 통째로 비껴가
「호스트   ( / )」라는 빈 계획을 출력하고 exit 0 했을 것이다. backlog.md 와
current-sprint.md 가 「--dry-run 을 먼저 볼 것」을 배포 첫 동작으로 지정하고 있어,
처음 배포하는 사람이 가장 먼저 밟는 경로가 정확히 거기다.


일부만 지정하면 빠진 것만 나열한다 (DEPLOY_ZONE 만 준 경우)

$ DEPLOY_ZONE=<존> bash scripts/deploy.sh --dry-run
배포 대상이 지정되지 않았다. 아래 환경변수를 넣고 다시 실행할 것 :
  - DEPLOY_HOST(인스턴스 이름)
  - DEPLOY_PROJECT(GCP 프로젝트)
  예) DEPLOY_HOST=… DEPLOY_ZONE=… DEPLOY_PROJECT=… bash scripts/deploy.sh --dry-run
$ echo $?
2
