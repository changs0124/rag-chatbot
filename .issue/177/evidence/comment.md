## 작업 요약

`backend.md` 「배포」가 [current-sprint](https://github.com/changs0124/rag-chatbot/blob/main/docs/04_tasks/current-sprint.md) 「진행 중」의 런칭 항목을 가리키게 했다.
**링크만 넣고 내용은 옮기지 않았다.**

## 전후

| | before | after |
| --- | ---: | ---: |
| `backend.md` 안의 `current-sprint` | **0건** | **1건** |
| `current-sprint.md` 안의 `02_architecture/backend` | 1건 | 1건 (그대로) |

이제 양방향이다. 종전에는 절차 정본에서 대기 항목으로 가는 길이 없어, 배포하는 사람이
#174 가 적어 둔 **대기 이슈 셋(#37 · #130 · #132)과 키 투입 순서**를 못 봤다.

## 이슈 제안과 다르게 배치했다

이슈는 **「상시 공개 - 자체 호스팅 서버」 끝부분**을 제안했다. 대신 **`## 배포` 맨 위 안내 직후**에 넣었다.

| | 이슈 제안 (`:536` 근처) | 채택 (`:313`) |
| --- | --- | --- |
| 읽는 시점 | 200줄을 다 읽은 **뒤** | 「배포」를 열면 **바로** |
| 적용 범위로 읽히는 것 | 바로 뒤가 `### 데모` 라 **상시 공개에만** 해당하는 말처럼 | `## 배포` 수준이라 **갈래와 무관하게** |

이슈가 적은 목적이 *"배포를 시작하기 전에 그쪽을 먼저 읽는다"* 인데, 끝에 두면 그 목적이
성립하지 않는다. **완료 조건은 「링크를 넣는다」이고 위치를 못 박지 않았으므로** 목적에 맞게 옮겼다.

`## 배포` 는 「두 갈래가 있다. 상시 공개는… 데모는…」으로 **길을 안내하는 자리**다.

## 넣은 내용

```markdown
**지금 무엇이 남았는지는 이 문서에 적지 않는다(#177).** 여기는 **절차**의 정본이고,
**남은 준비물 · 대기 중인 이슈 · 키 투입 직후 순서**는
[current-sprint](../04_tasks/current-sprint.md) 「진행 중」의 런칭 항목이 정본이다(#174).
**배포를 시작하기 전에 그쪽을 먼저 읽는다** — 키를 넣는 그 순간에만 값싸게 끝나는 일이 있다.
`#37` 은 `curl` 한 줄에 2초이고, 그때를 놓치면 키를 다시 꺼내야 한다.
같은 목록을 양쪽에 두지 않는다 — 한쪽만 고치면 갈라지기 때문이다.
```

## 검증

### 내용이 옮겨지지 않았는가 — 완료 조건이다

| 문자열 | before | after | |
| --- | ---: | ---: | --- |
| `TUNNEL_TOKEN` | 4 | 4 | 증가 0 |
| `OPENAI_VECTOR_STORE_ID` | 2 | 2 | 증가 0 |
| `--dry-run` | 2 | 2 | 증가 0 |
| `ALLOWED_ORIGINS` | 3 | 3 | 증가 0 |

옮기면 #174 가 한 곳으로 모아 둔 것이 다시 갈라진다. 넷 전부 그대로다.

### 섹션 이름 게이트 — 이 변경의 핵심 위험이었다

`check-doc-sections.sh` 는 **파일 참조가 바로 앞에 붙은** 「섹션」만 검사한다. 링크 뒤에 쓴
「진행 중」이 `current-sprint.md` 의 `## 진행 중` 과 글자까지 맞아야 통과한다.

```console
섹션 참조 29 건 대조        (before 27건)
섹션 참조 검사 통과
참조 수집 261건 · 실재 검사 249건
문서 참조 검사 통과
```

**27 → 29 로 늘고 통과했다**는 것이 근거다 — 단순히 「통과」가 아니라 **새 참조가 실제로 검사
대상에 들어갔다**는 뜻이다. 섹션 이름을 틀렸으면 여기서 잡혔다.

문서 게이트 전부 통과 · **건너뜀 0건**(`shellcheck` 을 Docker 로 실제 실행).
