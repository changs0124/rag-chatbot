## 3) 왜 흔들리는가 — 경우 분석 (상한 2, 요청 3번)

  고정 윈도우다. `increment(key) > limit` 이면 거절하고, 분이 바뀌면 count 0 으로 새 창이 열린다
  (RateLimiterService.java:114-123).

  세 요청이 두 창에 (k, 3-k) 로 쪼개질 때 거절 수 = max(0, k-2) + max(0, (3-k)-2) :

    (3,0) -> 1 + 0 = 1
    (2,1) -> 0 + 0 = 0   <- 여기서 깨진다
    (1,2) -> 0 + 0 = 0   <- 여기서도
    (0,3) -> 0 + 1 = 1

  **네 경우 중 둘에서 거절이 0건이다.** 경계가 1~2번째 또는 2~3번째 사이에 끼면 통과한다.
  경계가 끼는 확률이 낮아 평소에는 초록이고, 어느 날 갑자기 빨간불이 된다.
